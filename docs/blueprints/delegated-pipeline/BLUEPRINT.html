Blueprint

Delegated pipeline

Stamped at 72e911e: paths and symbols are true at this commit. Spec: issue #180.

At a glance explanation

The coder instance stops coding and starts delegating. Its routine's code step scans GitHub for the next eligible issue, has Codex implement it on Jorge's ChatGPT login, has Claude Code review it on his Claude login, loops at most three times, opens the PR on the right base branch, and returns a report that a Sonnet turn turns into an issue comment and an episode. The decision that shapes everything is that the pipeline is a code step, so no kinby model runs until the report exists and none runs when nothing is eligible.

Problem explanation

The first end-to-end run of the coder implemented one small issue for 6.72 USD at list prices, with zero cache hits, because kinby's own API-billed model did the reading, testing and editing. Jorge already pays for Codex and Claude Code subscriptions that cover that work, and both vendors document running their CLIs headless on a subscription. Meanwhile one webhook is the whole flow: nothing reviews the change before the PR opens, nothing picks the next issue in a tree of sub-issues, a second labeled issue diverges from main while the first PR waits, and a failed run leaves the issue labeled for the next wake to fail on again.

Solution explanation

You label issues ready-for-agent and link them as sub-issues of a parent, with blockers where order matters. From then on the container works the tree: the next eligible issue is implemented by Codex, reviewed by Claude Code with no shared context, fixed in the same Codex session, checked, pushed, and opened as a PR that stacks on its sibling's PR. You get a review request from GitHub, a comment on the issue, and an episode in kinby's memory. A failed run relabels the issue ready-for-human and tells you why, once. You merge every PR yourself until five have merged without your edits.

Bird's-eye flow reference

One figure of the whole feature. Boxes are modules or systems. Arrows carry the data that crosses. Decision ids lead the label where a decision picked the route.

  1. GitHub sends an issues or pull_request webhook to the receiver, which records a delivery (D9).
  2. The scheduler fires the delivery and the turn runner calls the code step with the signal and the routine's frontmatter arguments (D2).
  3. The step scans GitHub, picks the next eligible issue, and runs codex exec in the workspace to implement it (D4).
  4. The step runs claude -p twice, standards and spec, and feeds hard findings back to the same Codex thread, at most three rounds (D17, D5, D6).
  5. The step runs the checks, pushes the branch, opens the PR on its sibling's branch, registers the stack, and requests Jorge's review (D23, D13, D10).
  6. The step returns a pipeline report as routine data. The Sonnet turn comments a summary on the issue and the recap writes the episode (D22).

Module map reference

The routine's run.py imports one tool from a new package, kinby.factory. The turn runner loads run.py through the routine loader, unchanged. Nothing registers an entry point, so no other instance sees the pipeline as a model tool.

Interfaces

The functions and types other modules call. Argument names are the frontmatter keys where the routine supplies them.

pipeline.implement_ready_issue(signal, implementer_model, effort, reviewer_model, rounds, implement_seconds, review_seconds, fix_seconds, context) -> str | None
The code step. The turn runner calls it with the signal and the routine arguments. Returns the report as JSON, or None for no work.
scan.next_eligible(repository: Repository, signal: Signal) -> EligibleIssue | None
Decides whether the signal can change eligibility, then scans the repository for the oldest eligible issue and its base branch (D9, D13).

Implement, review, fix, review, up to the round cap. Owns the exit rule (D6, D17).
clients.implement(issue: EligibleIssue, settings: PipelineSettings, workspace: Path) -> CodexThread
One codex exec run with the implement-ticket skill expanded in the prompt. Returns the thread id and usage.
clients.fix(thread: CodexThread, findings: Findings, settings: PipelineSettings, workspace: Path) -> CodexThread
One codex exec resume run on the same thread with the findings (D5).
clients.review(issue: EligibleIssue, base: BranchName, settings: PipelineSettings, workspace: Path) -> Findings
Two parallel claude -p runs, standards and spec, read-only, with the adversarial-review briefs. Parses the tags.
pull_request.open(issue: EligibleIssue, loop: LoopResult, repository: Repository, workspace: Path) -> AgentPR
Checks, one fix round on a failing check, push, create, request review, register the stack (D23, D18). Raises PipelineFailure.
github.Repository
Every gh call: ready_issues(), agent_prs(), blockers(number), parent(number), create_pr(...), request_review(pr, login), register_stack(prs), swap_label(number, old, new).
process.run(command: Sequence[str], cwd: Path, limit: Seconds) -> Completed | Overrun
Runs a subprocess with a kill-on-overrun limit and captured output. The one place the pipeline touches subprocess (D21).

Ground-level flows reference

One subsection per step of the bird's-eye figure. Participants are the functions from the module map. Every message names the data shape that crosses.

Flow: wake and scan

  1. The turn runner calls the code step: input the signal and the routine arguments, output str | None.
  2. The step builds a PipelineSettings from the arguments and asks the scan for the next issue: input Repository and Signal.
  3. When the signal cannot change eligibility, the scan returns None without a GitHub call. Otherwise it reads the ready issues, the open agent PRs, and each candidate's open blockers and parent.
  4. The scan returns the oldest EligibleIssue with its base branch, or None.
  5. With an issue, the step runs the review loop and opens the PR, then returns the PipelineReport as JSON. With none, it returns None and the turn completes as no work.

Flow: implement and review loop

  1. Implement: input EligibleIssue and PipelineSettings, output CodexThread with the thread id and usage. The prompt names the ticket and expands the implement-ticket skill. The limit is implement_seconds.
  2. Review: input the issue and its base branch, output Findings. Two read-only claude -p processes run in parallel with the standards and spec briefs from the adversarial-review skill. The ticket text goes to a scratch file for the spec brief. The limit is review_seconds each.
  3. Exit test: no hard findings, or the round cap reached. Suggestions are included in the first fix only.
  4. Fix: input the same CodexThread and the Findings, output the thread with updated usage. The limit is fix_seconds. The last fix, or the implement run when no fix happens, writes the PR body to the workspace's ignored scratch location.
  5. Output LoopResult: the implement thread, one ReviewRound per review, and the findings still open.

Flow: checks, pull request and stack

  1. Checks: uv run ruff check ., uv run ruff format --check ., uv run ty check, uv run pytest, each through process.run. A failing check is one extra fix round outside the cap with the check output as the findings. A second failure raises PipelineFailure.
  2. Push: git push -u origin agent/<n>-<slug>. Never the default branch, never with force (D14).
  3. Create: input branch, base, title and the body file the implementer wrote, with Closes #n first and, after a capped loop, an "Open review findings" section. Output AgentPR.
  4. Request Jorge's review, so GitHub sends the email (D10).
  5. When the base is a sibling's branch, register or extend the stack with the PR numbers bottom to top (D18). A stack of one registers nothing.
  6. On failure the step swaps ready-for-agent for ready-for-human itself, then returns a failed PipelineReport for the model turn to comment on (D20).

Testing reference

It is the exact path the container runs (D2, D3) and it survives any split of the kinby.factory modules. Three small seams for the container files, the repo's skill set, and the manifest.

tests/test_instances.py for the routine CLI run on a coder copy; tests/test_routines.py for signal payloads; tests/test_container.py for the image and entrypoint; tests/test_packaged_skills.py for skill directories.

Cases

  1. An issue with an open blocker is skipped and the next eligible one is picked, flow wake and scan, protects D9 and D13.
  2. An issue covered by an open agent PR is never picked again, flow wake and scan, protects D9.
  3. A comment event, a foreign label, or a PR event on a non-agent branch returns no work with no gh call, flow wake and scan, protects D16.
  4. A sub-issue's base is its sibling's branch and the stack call lists both PRs bottom to top; a top-level issue registers no stack, flow checks, pull request and stack, protects D13 and D18.
  5. A clean review opens the PR after one round, flow implement and review loop, protects D6.
  6. Hard findings resume the same Codex thread id and the loop stops when the reviewer answers "No findings", flow implement and review loop, protects D5 and D6.
  7. Three rounds with hard findings still open the PR with an "Open review findings" section, flow implement and review loop, protects D6.
  8. Suggestions only end after one fix, flow implement and review loop, protects D6.
  9. A failing check gets one fix round; a second failure fails the pipeline, flow checks, pull request and stack, protects D20.
  10. A subprocess past its limit is killed, the issue is relabeled ready-for-human, and the report names the overrun, flow checks, pull request and stack, protects D20 and D21.
  11. The report carries the clients' token counts from their JSON, flow wake and scan, protects D25.
  12. The review request names the maintainer, flow checks, pull request and stack, protects D10.
  13. The image ships both CLIs at their pinned versions and the entrypoint writes the Codex skills config, protects D3 and D7.
  14. The named skills exist under .claude/skills with their reference files and the instance keeps only unslop, protects D7.
  15. The coder manifest loads with Sonnet 5, a 7200-second budget, and the routine's hourly schedule and arguments, protects D8, D16 and D21.

Open questions reference

Points the grilling did not settle. The agent building this stops and asks before acting on any of them.

  1. Placement of the pipeline as a package in the kinby distribution, kinby.factory, imported by the routine's run.py. The spec proposed it because a routine file runs standalone and cannot import siblings, and a single 400-line run.py is not a book. Options: kinby.factory as drawn; a separate installable tool package; one run.py. Default: kinby.factory.
  2. Whether Codex's [[skills.config]] entry takes a skills root or one skill path. Options: one entry for the directory; one entry per skill directory written by the entrypoint; a symlink from .agents/skills to .claude/skills in the clone with .agents/ ignored. Default: one entry for the directory, falling back to one per skill if the config rejects it.
  3. The stacks REST endpoint is a public preview and may change. Options: pin the API version header as documented; fall back to the branch topology alone if the call fails. Default: pin the header and treat a failed registration as a warning in the report, not a pipeline failure.
  4. Whether the Codex thread survives a container restart between rounds. The loop runs inside one turn, so a restart mid-loop fails the turn either way. Default: no persistence of the thread id beyond the turn.

Glossary reference

coding client
Claude Code or Codex run as a subprocess on the user's subscription to implement or review a change. New term.
delegated pipeline
The coder routine's code step: scan, implement, review rounds, checks, PR, report. New term.
review round
One review by the reviewer client and the fix that answers it. New term.
agent PR
A pull request the pipeline opened, on an agent/ branch, closing one issue. New term.
stack
A parent issue's agent PRs, each based on the previous, registered as a GitHub stacked pull request set. New term.
eligible issue
An open issue labeled ready-for-agent with no agent PR covering it and every blocker closed or covered within its stack. New term.
pipeline report
The one-page record the code step returns as routine data. New term.
code step
A routine's own deterministic code that runs before the model and may report no work.
no work
A completed turn whose code step found nothing for the model to do. Neither model runs.
signal, delivery, receiver, scheduler
An inbound stimulus; its recorded acceptance; the listener that records it; the coordinator that fires it.
episode
One distilled record of a turn in the knowledge graph, written by the recap.
