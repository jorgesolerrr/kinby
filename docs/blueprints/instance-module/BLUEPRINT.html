Instance module: init, manifest, discovery

Stamped at 6aa4a52: paths and symbols are true at this commit. Source: grilling on #4, spec #13, slice tickets #14–#20. The code is the second source of truth.

At a glance explanation

You run kinby init <dir> and get a directory you can read end to end. Then kinby instance show and kinby run find that directory the way git finds a repo and print what kinby sees. The solution is one package, kinby.instance, that owns three things: the canonical file names of an instance (layout.py), the parse and validation of kinby.toml into frozen dataclasses (manifest.py), and the three-rule lookup that turns "where am I" into "which instance" (discovery.py). The decision that shapes everything else is D1: an instance is one directory, the workspace lives under it, and runtime state lives in its .state/. Tarring the directory moves the instance, and one container image serves every instance.

Problem explanation

Before this feature, a self-hoster had nothing to install and nothing to point kinby at. The repository held a learning project (agent/, main.py, a package named agent). There was no notion of an instance on disk, and no command created or located one. Every later piece (the loop, the gate, memory, evals) needs a place to plug into, and that place did not exist.

Solution explanation

pip install kinby gives you a kinby command. kinby init <dir> writes a starter instance where every extension point is a real file with a comment saying what it is for. It refuses to touch a directory that already holds kinby.toml. kinby.toml has one required setting, [models].main, and never holds a secret. kinby instance show prints the resolved instance: id, path, which discovery rule matched, models, workspace, conventions, state dir. kinby run prints the same summary, applies --model for the session without editing the file, and opens the REPL. A bad manifest fails with a message that names the key. A generic Docker image mounts any instance at /instance.

Bird's-eye flow reference

The CLI either writes a starter instance or resolves one, loads it from disk, validates it, and prints it. Boxes are the functions other modules call. Arrows carry what crosses.

  1. main parses argv. For init it calls init_instance(Path(dir), model=…), which writes the starter tree and returns the resolved path (D4). It raises InstanceExistsError when kinby.toml is already there.
  2. For every other command, _load_selected_instance reads the explicit directory (--instance beats the positional argument). When one is given, it calls load_instance(path, model_override=…) directly. The override is set only for run --model.
  3. When no directory is given, main calls discover_instance(model_override=…). The three remaining rules run in order (D7), and the first hit names its MatchingRule.
  4. discover_instance calls load_instance(path, matching_rule=…, model_override=…).
  5. load_instance reads the instance directory: it loads .env into the environment without overriding existing variables (D3), then parses kinby.toml with tomllib.
  6. RawManifest.model_validate checks the table: required keys, types, unknown keys (D9, D13). This is the focal step: every user-facing manifest error except the override's own form check originates here.
  7. _manifest turns the validated RawManifest into a Manifest: it applies the session override to models.main, defaults recap, resolves paths, and keeps only the conventions that exist (D6, D8).
  8. load_instance returns an Instance to main, and _print_instance renders it. For run, main then opens the REPL.

Module map reference

The modules the feature created, the two callers that depend on them today, and their external dependencies. The three leaf modules are drawn as one node because every consumer imports at least two of them.

Interfaces

Everything below is re-exported from kinby.instance. Clients import the package, never the submodules.

init_instance(directory: Path, model: str = PLACEHOLDER_MODEL) -> Path
Writes the starter tree at directory, creating it when absent, and returns the resolved path. Raises InstanceExistsError when kinby.toml already exists. Called by main for kinby init.
discover_instance(*, model_override: str | None = None) -> Instance
Runs the KINBY_INSTANCE, walk-up, and home-default rules (D7) and loads the first hit. Raises InstanceNotFoundError when none matches, ManifestError when the hit does not load. Called by _load_selected_instance when no directory is given.
load_instance(directory: Path, *, matching_rule: MatchingRule = "explicit directory", model_override: str | None = None) -> Instance
Loads .env, parses and validates kinby.toml, and tags the result with matching_rule. Called by _load_selected_instance for an explicit directory, by discover_instance, and by tests that need an Instance.
reload_manifest(instance: Instance, *, model_override: str | None = None) -> Manifest
Re-reads the manifest of an already resolved instance, keeping its matching_rule and reapplying the session override (D6). Called by LangGraphRunner.prepare_for_turn at every turn boundary.
Instance, Manifest, Models, Workspace, Conventions, Memory
Frozen dataclasses. See Data shapes.
InstanceExistsError, InstanceNotFoundError, ManifestError
The three exceptions main translates into a stderr line and exit 1.
PLACEHOLDER_MODEL
"provider:model", the value init writes when --model is omitted.
kinby.instance.layout
String constants for every name in an instance directory (MANIFEST_NAME, STATE_DIR, WORKSPACE_DIR, …). Not re-exported. The only module allowed to spell a path.

Ground-level flows reference

Two flows: init writes an instance, and show and run resolve one. Participants are the functions from the module map.

Flow: init

  1. main(["init", dir, "--model", m]): input argv, output the call init_instance(Path(dir), model=m). Without --model, argparse passes PLACEHOLDER_MODEL.
  2. init_instance checks <dir>/kinby.toml: input the path, output a bool from Path.is_file.
  3. When the manifest exists, init_instance raises InstanceExistsError("instance already exists: <path>") before creating anything. main prints it to stderr and returns 1.
  4. Otherwise init_instance creates the directory and writes, in order, kinby.toml (with id = _slugify(dir.name) and main = m), SYSTEM.md, permissions.toml, memory/profile.md, .gitignore, tools/README.md, skills/README.md, routines/README.md, then creates empty workspace/ and .state/. Every written file starts with a comment (D4).
  5. init_instance returns directory.resolve(). main prints Created instance at <path> and returns 0. The model placeholder is not validated here.

Flow: show and run

  1. _load_selected_instance reads args.instance_directory or args.directory. model_override is --model for run, else None. Output: a call to load_instance or to discover_instance.
  2. With an explicit directory, load_instance(Path(dir), model_override=…) runs with the default matching_rule, "explicit directory".
  3. Without one, discover_instance tries the rules in order (D7): KINBY_INSTANCE; cwd and each of its parents, testing candidate / "kinby.toml"; ~/.kinby/default. Output: a path plus a MatchingRule literal. When nothing matches, it raises InstanceNotFoundError("No kinby instance found. Run `kinby init <directory>` first.").
  4. discover_instance calls load_instance(path, matching_rule=rule, model_override=…).
  5. load_instance calls load_dotenv(<instance>/.env, override=False) (D3). Output: environment variables added, existing ones kept.
  6. load_instance opens <instance>/kinby.toml in binary mode and calls tomllib.load. A missing file becomes ManifestError("kinby.toml: not found in <path>"). A parse error becomes ManifestError("kinby.toml: <decoder message>"). Output: a TOML table.
  7. RawManifest.model_validate(table) checks required keys, types, and unknown keys at every level (D13). A ValidationError becomes ManifestError("<dotted key>: <message>") through _manifest_error, which reports the first error (D9). Output: a RawManifest.
  8. _manifest(instance_path, raw, model_override) validates the override's provider:model form, replaces main with it, defaults recap to the value after the override, resolves state_dir and workspace.path against the instance, and keeps only the convention entries that exist (D6, D8). Output: a Manifest.
  9. load_instance returns Instance(path, manifest, matching_rule), through discover_instance when that was the caller.
  10. main calls _print_instance(instance), which writes the summary to stdout. For show it returns 0. For run it then builds the dispatcher and opens the REPL. Any InstanceNotFoundError or ManifestError from steps 3 to 8 is printed to stderr and main returns 1.

The starter tree init_instance writes (D4):

<dir>/
  kinby.toml          # id = "<slug>", [models] main = "<--model or provider:model>"
  SYSTEM.md           # behavior prompt
  permissions.toml    # comment only; the gate is not built
  memory/profile.md   # comment only
  tools/README.md     # "kinby does not load tools from the workspace"
  skills/README.md
  routines/README.md
  workspace/          # empty
  .state/             # empty
  .gitignore          # .state/ and .env

_slugify NFKD-normalizes the directory name, strips combining marks, lowercases, replaces every run of characters outside [a-z0-9] with -, trims dashes, and falls back to instance when nothing is left. My Agent becomes my-agent.

kinby instance show output, in order: id, persona name (when set), path, matching rule, models: with main, recap, embed (not configured when absent), workspace: <path> (present|missing), source (when set), conventions: with instructions: and skills: (only when at least one exists), state dir.

Container contract (D10), from Dockerfile and docs/container.md: python:3.14-slim, pip install ., ENV KINBY_INSTANCE=/instance, VOLUME ["/instance"], ENTRYPOINT ["kinby"], CMD ["run"]. The entrypoint does not clone a workspace yet.

Testing reference

Seams
One. kinby.cli.main([...]) invoked in-process with tmp_path, capsys, and monkeypatch for cwd, HOME, USERPROFILE, KINBY_INSTANCE, and stdin (D11). No test imports discovery or manifest internals. reload_manifest is tested through the public kinby.instance surface in tests/test_run.py because its caller sits inside a model turn.
A good test here
Write a kinby.toml into a temp directory, call main, then assert on the exit code, on lines of stdout, on stderr, and on files on disk. A test that survives renaming every private helper in manifest.py is at the right altitude.
Prior art
None before this feature. This feature set the pattern. tests/test_thread_cli.py follows it.

Cases

  1. init writes the documented tree and every file starts with a comment, flow init, protects D4.
  2. init on a directory with kinby.toml exits non-zero, writes to stderr, and changes nothing, flow init, protects D4.
  3. init writes id as the slug of the directory name, flow init, protects D5.
  4. init --model lands in the manifest; without it the placeholder is written and not validated, flow init, protects D4.
  5. instance show <dir> reports id, persona name, path, explicit directory, models with recap defaulted, workspace present with source, and a relative state_dir resolved against the instance, flow show and run, protects D1 and D6.
  6. Missing models.main, a malformed model string (main, recap, embed), and an unknown key at each level fail naming the key, flow show and run, protects D9.
  7. A missing default workspace is reported as missing; absolute state_dir and workspace.path pass through, flow show and run, protects D1.
  8. <instance>/.env is loaded and never overrides an existing environment variable, flow show and run, protects D3.
  9. Each discovery rule alone: KINBY_INSTANCE, walk-up from workspace/sub/dir, home default, flow show and run, protects D7.
  10. Precedence: --instance beats KINBY_INSTANCE; KINBY_INSTANCE beats walk-up and home default; walk-up beats home default, flow show and run, protects D7.
  11. No instance: exit non-zero, stderr names kinby init, ~/.kinby is not created, flow show and run, protects D7.
  12. Conventions: nothing listed when disabled or absent; defaults listed when enabled; custom lists in declared order; missing entries omitted; non-list and non-boolean values fail naming the key; a tools/ directory in the workspace is never listed, flow show and run, protects D8.
  13. run --model shows the override, leaves the file byte-identical, opens the REPL on an empty stdin, and exits 0, flow show and run, protects D6 and D12.
  14. reload_manifest reads an edited manifest and reapplies the override to main and recap, flow show and run, protects D6.
  15. Both examples/instances/* load through instance show; only coding-agent lists conventions, flow show and run, protects D4 and D8.
  16. The built image has KINBY_INSTANCE=/instance, volume /instance, entrypoint kinby, command run, and instance show on a mounted example reports matching rule: KINBY_INSTANCE, flow show and run, protects D10.

The spec left these open and the code does not settle them. The agent building on this module stops and asks before acting on any of them. The earlier question "who calls reload_manifest" is settled: LangGraphRunner.prepare_for_turn in src/kinby/core/turn_runner.py.

  1. When embed becomes required. The manifest accepts embed as optional and nothing checks it. Options: the memory spec (#8) validates it when a feed that needs it is enabled; show warns when a feed is enabled without it. Default: leave it to #8, as the spec says.

Glossary reference

Instance
One kinby deployment: a directory that owns its behavior configuration, memory, and transcripts. Here, any directory holding kinby.toml.
Instance discovery
The ordered lookup that selects an existing instance when a command does not name one. The matching rule is part of the result.
Manifest
kinby.toml, the portable description of an instance's identity and configuration. No secrets, no runtime state.
Workspace
The directory holding the user's own work that an instance acts on. Lives under the instance and is never written to by kinby on its own behalf.
Conventions
The workspace's instruction files and skill directories an instance may read as extra behavior sources. Named explicitly in the manifest.
Persona name
The per-instance display name, persona_name in the manifest. Distinct from kinby, the project.
Session
One run of the agent loop against a thread. The unit --model overrides for.
Turn
One user-to-agent cycle. The boundary at which the manifest is re-read.
