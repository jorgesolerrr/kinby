Blueprint

Recap writer

Stamped at fbab226: paths and symbols are true at this commit. Decided in ticket #9 (Recap and memory writer), specified in spec #82, recorded in ADR 0017.

At a glance explanation

After every turn, kinby writes one episode into memory/graph/: what happened, what was decided, what should have gone differently, and the path of tools the agent took. A runtime-owned RecapWriter does this after the turn's closing event, with one structured call to models.recap whose lens comes from the instance's RECAP.md. The decision that shapes everything else is that the recap runs outside the turn and marks itself with a memory.recapped event, so the turn never waits and the event log alone says which turns are covered.

Problem explanation

You ask your agent to fix a failing test. It reads six files, runs the suite twice, edits one function, and the turn completes. The transcript store holds every event of that turn. The knowledge graph holds nothing, because nothing writes episodes: the graph feed shipped with a facade, a store, and four tools, and only remember writes, and only when the model chooses to. Next week, in another thread, the same class of failure comes up. memory_search returns no episode, and the agent rediscovers the path from zero. You also have no record of what the agent thinks it should have done differently, so the same detour repeats.

Solution explanation

When a turn ends, the runtime recaps it. The recap reads that turn's events, extracts the tool path deterministically, asks the recap model for a short draft with fixed sections, and writes one episode. The turn is already over when the recap starts, and the next turn starts whether or not the recap has finished. You tune what a retrospective means for your agent in RECAP.md, next to SYSTEM.md: a coding agent asks about tests skipped and paths that could have been shorter, a support agent asks about tone. You can turn the recap off in kinby.toml. If the process dies or the model errors, the next start catches up every turn without a memory.recapped event. Recap tokens appear in your usage.

My view on the trade-off: a graph node would have been the obvious place for this and it is the wrong one. The turn's checkpoint history should hold only what the model did, and a memory write that fails should never fail a turn. Paying for that with one more event type is cheap.

Bird's-eye flow reference

The whole feature end to end. Boxes are modules, files, and systems. Arrows carry the call, event, or data that crosses them.

  1. Turns appends the turn's closing event to EventLog: turn.completed, turn.failed, or turn.interrupted (D11).
  2. Turns calls RecapWriter.schedule(thread_id, turn_id) and returns at once (D2). The turn task ends here.
  3. RecapWriter reads the turn's events from EventLog.stored(thread_id) and keeps the slice between turn.started and the closing event (D7).
  4. RecapWriter reads RECAP.md from the instance root, or uses the shipped default lens when the file is missing (D8).
  5. RecapWriter invokes models.recap once with the frame and the lens and gets a RecapDraft (D4). Under policy off this step is skipped (D3).
  6. When the draft says keep, RecapWriter calls Memory.remember with an Episode, and GraphStore writes one markdown node (D1, D6, D13).
  7. RecapWriter appends memory.recapped under the turn's id, with the node id or none and the recap's token totals (D5).
  8. usage_totals reads memory.recapped events and folds their tokens into the turn and thread totals (D12).

Interfaces

The calls other modules make. RecapWriter is new; the rest are existing signatures that gain a parameter or a field.

RecapWriter.schedule(thread_id: UUID, turn_id: UUID) -> None
Queues one recap and returns. Called by Turns after the closing event. A turn already covered by memory.recapped is a no-op.
async RecapWriter.catch_up() -> None
Scans the event log for closed turns without a marker and schedules them oldest first. Called once by the CLI before any turn runs.
async RecapWriter.drain() -> None
Waits until the queue is empty and the running recap is done. Called by tests and evals.

Ground-level flows reference

Two flows: the recap after a turn, and the catch-up at process start. Participants are the functions and modules from the module map.

Flow: recap after a turn

  1. Turns._finish (or Turns.interrupt) appends the closing event: input TurnCompleted | TurnFailed | TurnInterrupted, output Event.
  2. Turns calls after_turn(thread_id, turn_id), which is RecapWriter.schedule. Output: none. The turn task ends.
  3. The writer's worker takes the item and reads EventLog.stored(thread_id): output list[Event], filtered to event.turn_id == turn_id. When a MemoryRecapped is already there, the item is dropped.
  4. The writer builds the trace from the ToolCall payloads in order: output tuple[str, ...] of tool names and one summary line per call. It renders the turn's events into the frame: user message, joined MessageDelta text, each ToolCall with its ToolResult cut to the budget, the closing event.
  5. The writer reads RECAP.md or takes the default lens, reloads the manifest for models.recap and the policy, and invokes the recap model with structured output: output RecapDraft. Under off there is no call and the draft is trace-only with keep set to whether any tool ran.
  6. When draft.keep, the writer calls Memory.remember with an Episode (date today, thread, turn, description, subjects, tools, body with the four sections): output NodeId.
  7. The writer appends MemoryRecapped(node, input_tokens, output_tokens) under the turn's id: output Event.
  8. On a model error the writer appends Warning under the turn's id and writes nothing. The turn stays uncovered for the next catch-up.

Flow: catch-up at process start

  1. kinby run and the REPL path in kinby.cli.main build the turn configuration, then await RecapWriter.catch_up() once. Input: none.
  2. The writer reads EventLog.all_events(): output Iterator[Event].
  3. The writer groups events by turn_id and keeps turns with a closing event and no MemoryRecapped: output a list of (thread_id, turn_id) in log order.
  4. For each, the writer calls its own schedule. The queue holds them in order; one worker task drains it.
  5. catch_up returns. Turns are served while the recaps run. A turn that closes meanwhile is scheduled behind them.

Testing reference

Seams
The dispatcher built with a TurnConfig whose runner is scripted and whose recap writer takes a scripted recap model factory (D2, D4). The recap model factory is the one new injection point; it mirrors the model factory LangGraphRunner already takes. Node shape is checked at the memory facade seam; tokens at usage.get.
A good test here
Starts a turn through thread.turn.start, awaits RecapWriter.drain(), then asserts what a subscriber saw on thread.subscribe, which files exist under memory/graph/, and what memory_open returns. It never inspects the writer's queue.
Prior art
tests/test_turns.py (scripted runner, restart cases), tests/test_memory.py (facade against a real instance in tmp_path), tests/test_usage.py, tests/test_instance_show.py.

Cases

  1. A completed turn with tool calls yields one episode with turn, tools, four sections, and a memory.recapped event naming the node, flow recap, protects D1, D4, D5.
  2. A draft with keep false yields no node and a memory.recapped with no node, flow recap, protects D6.
  3. Under off, a turn with tools yields a trace-only episode and no model call; a chat-only turn yields no node; both are marked, flow recap, protects D3, D6.
  4. A failed turn and an interrupted turn are both recapped, flow recap, protects D11.
  5. A second turn starts on the same thread while the first recap is blocked, flow recap, protects D2, D14.
  6. A recap model error yields a warning and no marker; a new dispatcher's catch_up then writes the episode, flows recap and catch-up, protects D5.
  7. A closing event with no marker in a pre-seeded log is recapped by catch_up before the first turn, flow catch-up, protects D5.
  8. The text of RECAP.md reaches the recap model; a missing file sends the default lens; an edit between two turns reaches the second recap, flow recap, protects D8.
  9. usage.get adds recap tokens to the turn and thread totals and reports them in the recap fields, flow recap, protects D12.
  10. The recap never appends anything but memory.recapped or warning, and never writes a fact, flow recap, protects D10.

Open questions reference

Points the grilling did not settle. The agent building this stops and asks before acting on any of them.

  1. What the REPL shows for memory.recapped. Options: ignore it; print one dim line naming the node. Default: ignore.
  2. The tool-result truncation budget in the frame. Options: 800 characters per result; 2000. Default: 800, as a module constant.
  3. Whether kinby init writes a starter RECAP.md or leaves the file absent and relies on the default lens. Options: write it; leave it. Default: write it, so the user sees what to edit.
  4. Whether the writer loads the recap model once per process or per recap. Options: per recap, so a manifest edit to models.recap applies at once; per process. Default: per recap, matching how the turn model is reloaded.

Glossary reference

turn
One user-to-agent cycle within a thread. What the user calls a task. Earns at most one episode.
episode
One distilled record in the knowledge graph of a single turn: what happened, what was decided, what should have gone differently, and the tools and path the agent used.
recap
The model call the runtime makes after a turn ends, and the writing it does. Runs outside the turn, never delays the next one, never writes facts.
recap policy
The instance setting that says whether the recap runs after every turn or not at all.
recap prompt
The instance's own instructions to the recap model. kinby supplies the frame and a default lens; the instance may replace the lens.
transcript store
The canonical record of every conversation. The event log. The knowledge graph is derived from it, never the reverse.
event
One sequence-numbered record in a thread's durable history. memory.recapped is one.
memory facade
The single interface through which kinby recalls, opens, remembers, and forgets. The writer is a core caller of it.
session
One run of the agent loop against a thread. Not a model call.
