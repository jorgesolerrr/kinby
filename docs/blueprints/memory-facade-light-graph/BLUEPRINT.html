Blueprint

Memory facade and the light graph

Stamped at e2d0491: paths and symbols are true at this commit.

At a glance explanation

The agent gets a memory it can query and the user gets memory files they can read and correct. One facade (recall, open, remember, forget) fronts every feed, and the first real feed is a knowledge graph of markdown nodes under memory/graph/, reached by the model through four gated tools. The decision that most constrains everything else is D1: core code calls the Memory Protocol, the model calls tools that wrap it, and there is exactly one implementation underneath.

Problem explanation

kinby forgets everything between threads except profile.md. Ask it what you decided about the eval harness last week and it has nothing. Hand it a support problem it already solved once and it starts from zero, re-deriving the same tool path it already walked. The transcript store records every conversation, but nothing reads it back. You carry the memory; the teammate should.

Solution explanation

Your instance grows a queryable memory. Episodes distill each finished task: what happened, what was decided, and which tools the agent ran, so the next turn on the same problem reuses the path instead of rediscovering it. Facts are atomic timestamped statements written the moment they are learned. You can open any node in an editor, fix it, or delete it, because every node is a markdown file in your instance directory. Forgetting leaves a tombstone, so a forgotten fact stays forgotten even though the transcript it came from is never rewritten.

Bird's-eye flow reference

The whole feature end to end. The top path is the graph feed: the model calls a memory tool, the tool calls the facade, the facade reads and writes node files. The bottom path is the files feed that already exists: the profile renders into the system prompt each turn.

One step per arrow, in order.

  1. The model streams a ToolCall for a memory tool into _call_tools.
  2. _call_tools asks gate.evaluate; reads pass, writes ask or deny by mode (D1).
  3. _call_tools invokes the memory tool with the model-supplied arguments (D3).
  4. The tool calls the one facade implementation, GraphStore (D1).
  5. GraphStore reads or writes GraphNode markdown files under memory/graph/ (D6).
  6. Unchanged files feed: assemble_system_prompt reads memory/profile.md each turn.
  7. The profile section rides the SystemMessage into the model.

Module map reference

The three new modules sit inside kinby.memory. The turn runner builds a GraphStore per turn and adds the four memory tools to the turn's snapshot. Nothing outside kinby.memory touches node files.

Interfaces

The functions and types other modules call.

Memory.recall(query, after=None, before=None) -> tuple[MemoryHit, ...]
Deterministic search over node descriptions and subjects (D12). Called by memory_search, later by the recap writer and evals.
Memory.open(node: NodeId) -> str
Returns the node body. Called by memory_open.
Memory.remember(fact: FactDraft) -> NodeId
Writes a fact node immediately (D4). Called by remember.
Memory.forget(node: NodeId) -> None
Tombstones a node (D5). Called by forget.
GraphStore(instance: Instance)
The graph feed: the one Memory implementation in this blueprint. Built by LangGraphRunner per turn.
memory_tools(memory: Memory, thread_id: UUID) -> tuple[Tool, ...]
Builds the four core tools over a facade, the skill_tool pattern. The runner adds each through ToolSnapshot.with_core.

Ground-level flows reference

Two flows cover the four tools. Participants are the functions from the module map. The gate check is a self-call on _call_tools because gate.evaluate is a pure function it calls inline.

Flow: recall walk

  1. The model calls memory_search: input query, after, before, all model-supplied (D12).
  2. gate.evaluate allows: memory_search is a read tool (D1).
  3. The tool calls Memory.recall: output tuple[MemoryHit, ...], newest first, capped at 20.
  4. An empty tuple is a valid result: the model rephrases instead of trusting a fuzzy match (D12).
  5. The model picks a hit and calls memory_open(node): output the node body as str.
  6. From an episode body the model can follow the thread id to the sibling session (D11).

Flow: remember and forget

  1. The model calls remember: input description, subjects, body (D4, D9).
  2. gate.evaluate answers ask: remember is a write tool and the mode is ask (D1).
  3. The interrupt parks the turn; the user's answer becomes an ApprovalDecision.
  4. Approved: the tool calls Memory.remember(fact: FactDraft), output NodeId; the store writes one markdown file under memory/graph/ (D6).
  5. Denied: the model gets an error ToolMessage and the turn continues, existing gate behavior.
  6. The model calls forget(node); the store writes a tombstone (D5); later recall and open exclude the node.
  7. forget passes the same gate ask as remember; the figure omits the repeat.

Testing reference

Seams
The Memory Protocol, tested directly against a real instance directory in tmp_path: the one new seam, and the same call surface the recap writer and evals use later (D15). The existing runner seam with a scripted model covers tool wiring and the gate.
A good test here
Asserts what the tools return, what files exist afterward, and what the model could see. Never index structures or private helpers.
Prior art
tests/test_gate.py (scripted model against a real instance), tests/test_system_prompt.py (prompt sections), tests/test_plugins.py (tool registration, reserved core names).

Cases

  1. Day lookup: recall bounded to one day returns that day's nodes, flow recall walk, protects D8.
  2. Last touched: recall(subject) returns hits newest first, flow recall walk, protects D8 and D12.
  3. Decision currency: two facts on one subject, the newest is the first hit, flow recall walk, protects D10.
  4. Literal search: a non-matching query returns an empty tuple, no fuzzy match, flow recall walk, protects D12.
  5. Cap: 25 matching nodes yield 20 hits, flow recall walk, protects D12.
  6. remember writes one markdown file under memory/graph/ with the D9 frontmatter, flow remember and forget, protects D4 and D9.
  7. forget removes the node from recall and open, and the file's tombstone survives, flow remember and forget, protects D5.
  8. An episode with a tools field is searchable and opens with its trace body, flow recall walk, protects D11.
  9. Runner: memory_search runs without approval in ask mode, flow recall walk, protects D1.
  10. Runner: remember asks in ask mode; deny returns an error ToolMessage and the turn continues, flow remember and forget, protects D1.
  11. Runner: after forget, a later memory_search in the same turn excludes the node, flow remember and forget, protects D5.

Out of scope reference

  • The episode writer: when recap runs and what its policy is. Ticket #9. This blueprint fixes the format it writes and the facade it calls.
  • Eval harness cases and numeric thresholds for the feed gates. Ticket #10. Only the metric definition (D13) is fixed here.
  • The RAG index feed. After the graph proves itself (D7); it may slip past v1.
  • Ingestion of external content (documents, email) and backfill.
  • Contract methods for memory (D14).
  • A vector or graph database. Graph backend graduation stays fog on the map until the memory evals run.

Open questions reference

Points the grilling did not settle. The agent building this stops and asks before acting on any of them.

  1. Node id and filename scheme. Options: date plus a slug of the description (2026-08-30-eval-harness.md); a UUID filename. Default: date plus slug, because human-legible filenames are the point of D6.
  2. Tombstone representation on disk. Options: a tombstone: true frontmatter flag on the node file; a separate tombstone list outside the nodes. Default: the frontmatter flag, so the record of the forgetting is as legible as the memory was.
  3. Frontmatter parsing. Options: extend the hand-rolled parser pattern from plugins/skills.py to cover list values; add a YAML dependency. Default: the hand-rolled parser, matching the existing pattern and adding no dependency.

Glossary reference

memory facade
The single surface through which anything recalls, remembers, or forgets. Core calls it directly; the model reaches it only through memory tools.
feed
One retrieval implementation behind the memory facade: the profile file, the knowledge graph, or the RAG index over the transcript store.
memory tool
A core tool exposing the facade to the model. Reads are read tools; remember and forget are write tools the gate governs.
episode
One distilled record of a task: what happened, what was decided, and the trace of what the agent did.
fact
An atomic, timestamped statement recorded the moment it is learned. The latest fact about a subject wins.
tombstone
The suppression marker a forget leaves. The ingestion pipeline never re-derives a tombstoned fact.
knowledge graph
The life wiki, queried by the agent on demand, never auto-injected. This blueprint builds its light markdown form.
transcript store
The canonical record of every conversation. The graph derives from it; it is never rewritten.
profile
The human-legible record of preferences and standing instructions, always present in context.
