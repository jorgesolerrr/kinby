Blueprint

Workspace snapshots

Stamped at 59b1390: paths and symbols are true at this commit.

At a glance explanation

Every turn gets an exact record of what it changed in the workspace, and the user can put the workspace back to the state before any turn. kinby snapshots the workspace into a shadow git repository under .state/ at both ends of every turn, records the tree ids on the turn's events, and answers thread.turn.diff and thread.turn.revert from those ids. The constraining decision is the shadow repository: one code path for repositories and notes folders, never a byte written into the user's .git, at the price of a blob copy on the first snapshot.

Problem explanation

A routine turn edits the workspace while nobody watches. When the user comes back, the event log tells them which tools ran and which paths were written, but not what the files looked like before or after. In a git workspace they can run git diff against the last commit, which mixes the turn's work with their own uncommitted edits and says nothing about which turn did what. In a notes folder they have nothing. Undoing a bad turn means reading the transcript and reversing each edit by hand, and the gate cannot lean on any undo because none exists (ADR 0014).

Solution explanation

Before a turn starts and again when it closes, kinby snapshots every file in the workspace that git would not ignore. The two tree ids ride on turn.started and on the closing event. In the REPL, /diff prints what the last turn changed, file by file and then as a patch. /revert shows the same list, asks for a yes, and restores the workspace to the state before that turn. A revert is recorded on the thread with its own snapshots, so the user can revert the revert. Nothing changes for the model: it has no snapshot tool, and the gate keeps its defaults.

Bird's-eye flow reference

One figure of the whole feature. Boxes are modules, stores and the git process. Arrows carry the call or the data that crosses. Decision ids lead the label where a decision picked the route.

  1. The REPL calls thread.turn.diff or thread.turn.revert through the contract client (D11, D12).
  2. The dispatcher validates the command and hands it to Turns, the same service that starts and interrupts turns.
  3. Turns asks WorkspaceSnapshots for a capture at every turn boundary (D4), and for a diff or a restore when the user asks (D2).
  4. WorkspaceSnapshots runs the git binary as a subprocess, with --git-dir pointing at .state/snapshots.git and --work-tree at the workspace (D2, D13).
  5. Every capture writes a commit and a ref into the shadow repository; a restore writes the workspace's files from a tree (D8).
  6. Turns records the tree id on turn.started, on the closing event, and on workspace.reverted in the event log (D7, D9).

Interfaces

The functions and types other modules call. Names marked new do not exist at the stamped commit.

WorkspaceSnapshots.open(state_dir: Path, workspace: Path, *, enabled: bool) -> WorkspaceSnapshots | None
New. Probes git --version, creates the bare repository under .state/snapshots.git when missing, and returns None when snapshots are off or git is absent, logging one warning for the absent case (D5). Called by turn_config in the dispatcher module.
WorkspaceSnapshots.capture(ref: str) -> TreeId
New, async. Stages the work tree with add -A, writes a tree and a commit, points ref at the commit, and returns the tree id (D2, D13). Raises SnapshotError when git fails.
WorkspaceSnapshots.diff(before: TreeId, after: TreeId) -> WorkspaceDiff
New, async. Runs git diff --numstat and git diff -p between two trees and returns the file list and the patch (D11).
WorkspaceSnapshots.restore(tree: TreeId) -> None
New, async. Runs git read-tree --reset -u against the work tree, so files present in the index but absent from the tree are removed and ignored files are untouched (D8).
SnapshotStore (Protocol)
New. The three methods above, which Turns depends on so tests pass a fake.
Turns.diff(command: ThreadTurnDiffCommand) -> ThreadTurnDiffResult
New. Resolves the target's before and after tree ids from the thread's events, then calls the store (D11). Raises SnapshotUnavailable when either id is None, NotFound for an unknown id, ThreadBusy for a running turn.
Turns.revert(command: ThreadTurnRevertCommand) -> AcceptedResult
New. Refuses with InstanceBusy unless running() and the claims are empty (D10), then captures, restores, captures and appends WorkspaceReverted (D9).
TurnConfig.snapshots: SnapshotStore | None

New Method constants in contracts.methods, scopes thread:read and thread:operate (D11).

Ground-level flows reference

Three flows: bracketing a turn, answering a diff, answering a revert. Participants are the functions from the module map.

Flow: bracket a turn

  1. Turns._wake calls capture with refs/kinby/snapshots/<thread>/<turn>/before after the turn claim and the daily budget check, before it appends anything (D4).
  2. WorkspaceSnapshots runs git add -A, git write-tree, git commit-tree and git update-ref as subprocesses and returns the tree id. When git fails, Turns logs a warning and continues with None (D5, D7).
  3. Turns appends TurnStarted with snapshot set to the tree id or None.
  4. The turn runs as today through TurnRunner.run or resume.
  5. Before the closing event, Turns._finish captures …/<turn>/after. The interrupt path captures after the task has stopped, before it appends TurnInterrupted (D4).
  6. Turns appends TurnCompleted, TurnFailed or TurnInterrupted with the after tree id. A parked turn appends nothing and captures nothing until it resumes and closes.
  7. With snapshots off or unavailable, every field is None and no git process runs.

Flow: diff a turn

  1. The REPL resolves the argument to one id on this thread: the last closed turn or revert when absent, else a full UUID or a prefix of eight or more characters that matches exactly one id (D12). Two matches print an error.
  2. It calls thread.turn.diff with ThreadTurnDiffCommand(thread_id, turn_id).
  3. Turns.diff reads the thread's events. For a turn, before is TurnStarted.snapshot and after is the closing event's snapshot. For a revert, before is WorkspaceReverted.previous and after is WorkspaceReverted.restored (D9).
  4. An id with no events raises NotFound. A turn without a closing event raises ThreadBusy. Either tree id being None raises SnapshotUnavailable, a new error code.
  5. WorkspaceSnapshots.diff runs git diff --numstat and git diff -p between the two trees and returns WorkspaceDiff(files, patch).
  6. The result is ThreadTurnDiffResult(turn_id, before, after, files, patch). The REPL prints one line per file, then the patch.

Flow: revert a turn

  1. The REPL resolves the id as for /diff, calls thread.turn.diff first and prints the file list, then asks Revert N files to before <id>? [y/N]. Anything but y stops here (D8, D12).
  2. It calls thread.turn.revert with ThreadTurnRevertCommand(thread_id, turn_id).
  3. Turns.revert raises InstanceBusy when running() or the claims are non-empty. running() already counts parked approvals, so a parked turn blocks a revert too (D10). A target with no before tree id raises SnapshotUnavailable. A store of None raises it too.
  4. It captures refs/kinby/snapshots/<thread>/<revert>/before; the tree id is previous (D9).
  5. It calls restore with the target's before tree, then captures …/<revert>/after; the tree id is restored and equals the target's before tree.
  6. It appends WorkspaceReverted(target_turn_id, previous, restored) on the thread with the revert's own id as the event's turn_id, the way ModePinned uses a fresh id today.
  7. AcceptedResult carries the revert id and the event sequence. The REPL prints Workspace reverted to before <id>.

Data shapes reference

Every type the feature adds or changes. TreeId is a forty-character hex string, an alias in contracts.models.

Two shapes that a figure cannot hold. The ref name is fixed so a user can list snapshots with plain git:

refs/kinby/snapshots/<thread_id>/<turn_id or revert_id>/before
refs/kinby/snapshots/<thread_id>/<turn_id or revert_id>/after

The git invocation shape, which is the whole of D2 in one line:

git --git-dir=<instance>/.state/snapshots.git --work-tree=<workspace> <subcommand>

Testing reference

Seams
Four. WorkspaceSnapshots against a real temporary directory and the real git binary, because the git semantics in D2, D8 and D13 are the feature. Turns with a fake SnapshotStore for the bracketing, the guards and the events (D4, D7, D9, D10). The dispatcher for the two methods and their scopes (D11). run_repl for the two commands (D12). The manifest and schema tests cover D5's switch, and the container test covers git in the image.
A good test here
Asserts the tree in the workspace, the events a subscriber sees, the result a method returns, or the text the REPL prints. Never the refs' commit ids, the git commands, or the fake's call order beyond the refs it was given.
Prior art
tests/test_turns.py, tests/test_repl.py, tests/test_schema.py, tests/test_container.py, tests/test_events.py.

Cases

  1. Two captures of an unchanged workspace return the same tree id, flow bracket, protects D4.
  2. A capture after a file edit yields a diff with one modified FileChange and a patch, flow diff, protects D2 and D11.
  3. An untracked file is captured and a file matching .gitignore is not, flow bracket, protects D13.
  4. A workspace that is itself a git repository never has its .git captured, flow bracket, protects D13.
  5. A notes folder with no .git is captured, diffed and restored the same way, flow bracket, protects D2.
  6. Restore removes a file added since the target tree, restores an edited one, and leaves an ignored file untouched, flow revert, protects D8 and D13.
  7. A completed turn's turn.started and turn.completed carry the before and after tree ids the fake returned, flow bracket, protects D4 and D7.
  8. A failed turn and an interrupted turn carry the after tree id, flow bracket, protects D4.
  9. A capture that raises leaves snapshot as None and the turn completes, flow bracket, protects D5.
  10. With no store, no field is set and nothing is called, flow bracket, protects D5.
  11. thread.turn.diff for a closed turn returns both ids and the fake's diff, flow diff, protects D11.
  12. thread.turn.diff for a turn with a None id returns SNAPSHOT_UNAVAILABLE; for a running turn THREAD_BUSY; for an unknown id NOT_FOUND, flow diff, protects D7 and D11.
  13. thread.turn.revert while a turn runs on another thread returns INSTANCE_BUSY and calls nothing, flow revert, protects D10.
  14. thread.turn.revert while an approval is parked returns INSTANCE_BUSY, flow revert, protects D10.
  15. A revert captures, restores the target's before tree, captures, and appends workspace.reverted with the three ids, flow revert, protects D9.
  16. Reverting a revert restores its previous tree, flow revert, protects D9.
  17. thread.turn.diff on a revert id diffs previous against restored, flow diff, protects D9.
  18. The two methods carry thread:read and thread:operate, flow diff and revert, protects D11.
  19. /diff with no argument prints the last closed turn's files and patch, flow diff, protects D12.
  20. /diff with an eight-character prefix that matches one id prints it; a prefix that matches two prints an error, flow diff, protects D12.
  21. /revert prints the file list, asks, and calls nothing on n; calls thread.turn.revert on y and prints the confirmation, flow revert, protects D8 and D12.
  22. [workspace] snapshots = false loads, appears in the schema, and yields no store, flow bracket, protects D5.
  23. The container image answers git --version, flow bracket, protects D5.

Out of scope reference

  • A snapshot tool or diff tool for the model. The model can run git itself in a git workspace.
  • The turn's diff as recap input. Graduated to its own map ticket now that the diff exists.
  • Files changed per turn in turn metrics and kinby stats. The event log carries the ids, so it can be derived later without a new record.
  • Pruning snapshot refs or running git gc on the shadow repository (D14). Fog on the map.
  • Diffing a running turn against the live work tree. The REPL never asks between messages, and a running turn answers THREAD_BUSY.
  • Reverse-applying one turn's patch while keeping later turns (D8).
  • Any change to the gate's presets (D6).

Open questions reference

Every question the grilling asked is settled above. Two implementation details are left to the builder and need no decision from the user.

  1. Whether the shadow repository sets core.autocrlf=false and core.safecrlf=false at creation so a Windows checkout never rewrites line endings on restore. Default: set both.
  2. Whether a nested repository inside the workspace (a submodule or a vendored clone) is captured as a gitlink, which is git's default, or skipped. Default: git's default, documented in the skill that explains snapshots.

Glossary reference

Workspace
The directory holding the user's own work that an instance acts on. Never written to by kinby on its own behalf.
Workspace snapshot
The recorded state of every non-ignored file in the workspace at one turn boundary.
Workspace revert
A user's request to put the workspace back to the snapshot taken before a chosen turn, recorded on the thread with its own snapshots.
Turn
One cycle of agent work within a thread, the unit of checkpoint bracketing.
Graph checkpoint
The turn runner's durable working state for a thread. Not a workspace snapshot.
Event
One record on a thread in the transcript store, with a monotonic sequence.
Permission mode
A named preset of gate rules a thread runs under. Unchanged by this feature.
Contract
The typed methods clients call; two are added here.
