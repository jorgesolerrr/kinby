Blueprint

Routines, wakes and budgets

Stamped at d131af9: paths and symbols are true at this commit.

At a glance explanation

You get routines: a directory under routines/ with a prompt, a cron line and an optional run.py that runs before the model, plus kinby serve to keep the instance alive so they fire, and a [budgets] table that bounds every turn by steps, tokens and seconds and the instance by USD per day. Every fire is an ordinary turn on a fresh thread, started through one wake entry point on the turn service that records its origin on turn.started. The decision that constrains the rest is that the event log stays the only run history: last run, next run and missed fires are all read from the origin on turn.started, so the scheduler keeps no file of its own.

Problem explanation

Your kinby only acts when you type. kinby init writes a routines/ directory with a README that promises a trigger, a prompt and a destination, and nothing in the package reads it. kinby run is the REPL; in a container with no terminal it reads end of input and exits, so nothing stays alive to fire anything. On the other side, no turn is bounded. LangGraphRunner._invoke calls graph.ainvoke without a recursion limit, the model and tools cycle runs until the model stops, the only clock anywhere is the 120 second bash timeout, and turn_metrics computes cost per turn that nothing reads back. The one stop is thread.turn.interrupt from a REPL you may not have open.

Solution explanation

You write routines/nightly/ROUTINE.md: frontmatter with schedule: 0 3 * * *, a mode and budgets, and the prompt as the body. You add run.py beside it when deterministic code should run first: it is a kinby tool like any other, the model never sees it, and when it returns nothing the model is not called. You start kinby serve in the container. At three in your declared time zone the scheduler creates a thread named after the routine, wakes it with the prompt, and the turn runs under the gate, the recap and the statistics like every other turn. kinby routine list shows the last and next run of each routine; kinby routine run nightly fires it now. If the box was off at three, the routine fires once when it comes back. Only one turn runs at a time: a routine waits for you, and you wait for a routine, with a line that says which one. An approval during a routine run parks the turn, and the REPL shows it when you next open the instance. Under [budgets], a turn that loops, bloats or stalls fails with the budget's name on the thread, and a day that has spent its money refuses the next turn before it starts. I think the wake is the part that matters beyond this ticket: signals, peer messages and subagent completions will all start turns, and they now have exactly one door to come through.

Bird's-eye flow reference

One figure of a scheduled fire end to end. Boxes are modules or systems. Arrows carry the call or data that crosses. Decision ids lead the label where a decision picked the route. User turns enter Turns through thread.turn.start on the same wake path and are left out of the figure.

Prose walkthrough, one step per arrow.

  1. kinby serve boots the instance like kinby run and calls Scheduler.start(); kinby routine run calls Scheduler.fire(name) once instead.
  2. On each pass the scheduler calls load_routines(instance), which reads every routines/<name>/ROUTINE.md and its optional run.py (D4, D19).
  3. When a routine is due and the turn service is idle, the scheduler creates a thread in ThreadStore and calls Turns.wake(thread_id, prompt, RoutineOrigin) (D1, D7, D9).
  4. Turns.wake checks the daily cost budget from the turn preparation, then appends turn.started with the origin to the EventLog (D11, D12).
  5. The turn service calls LangGraphRunner.run(turn, emit), which loads the routine by name, combines its budgets with the manifest's, and runs the code step through the gate with the routine's mode (D5, D11).
  6. When the code step returns nothing the turn completes here (D6). Otherwise the runner renders the cue, prompt and payload with render_wake and streams the model under the recursion limit and the timeout (D11, D13).

Interfaces

The functions and types other modules call, with their signatures.

Turns.wake(thread_id: UUID, message: str, origin: TurnOrigin) -> AcceptedResult
Starts one turn with an origin. Turns.start calls it with UserOrigin(); the scheduler calls it with a RoutineOrigin. Refuses with BudgetExceeded, ModelUnpriced or InstanceBusy before appending anything.
Turns.idle() -> None
Waits until no turn is running on any thread. The scheduler awaits it before a pass.
Turns.running_routine() -> RoutineOrigin | None
The routine whose turn is running, if any. Named in the InstanceBusy message.
Scheduler(instance, event_log, store, turns, *, now=_utc_now)
The reactor. start() spawns the worker, stop() cancels it, fire(name, trigger) -> AcceptedResult creates a thread and wakes it, list() -> RoutineListResult folds routines and history, drain() waits for the current pass.
load_routines(instance: Instance) -> tuple[tuple[Routine, ...], tuple[Warning, ...]]
Reads every routines/<name>/ROUTINE.md and its run.py. Broken routines become warnings, like skills.
load_tool_file(path: Path) -> tuple[Tool, ...]
The registry's file loader, made public so the routine loader reads run.py the same way tools/ is read.
daily_cost(events: Iterable[Event], prices: Mapping[str, ModelPrice], today: date) -> DailyCost
Sums the cost of turns closed on the UTC day through turn_metrics; spent is none when any of them is unpriced.
effective_budgets(instance: Budgets, routine: Budgets) -> tuple[Budgets, tuple[Warning, ...]]
Takes the lower of each per-turn budget; a routine value above the instance value warns and the instance value applies.
check_daily_budget(budgets: Budgets, cost: DailyCost, model: str, prices: Mapping[str, ModelPrice]) -> None
Raises ModelUnpriced when usd_per_day is set and the model or the day is unpriced, BudgetExceeded when spent has reached the limit.
render_wake(origin: TurnOrigin, message: str, payload: str | None) -> str
The user message for the model: the message as is for a user origin; a bracketed routine cue, the prompt, and the payload in a tagged data block for a routine origin.
boot_instance(instance: Instance, *, event_log: EventLog, model_override: str | None = None) -> InstanceRuntime
The one boot shared by kinby run, kinby serve and kinby routine run: builds the dispatcher with turns, the recap writer and the scheduler, and returns them together.

Ground-level flows reference

One subsection per flow named in the bird's-eye figure. Each has a sequence whose participants are the functions from the module map, then a numbered step list naming the data shape at each hop.

Flow: a scheduled fire

  1. The scheduler's pass finds a due routine, waits on Turns.idle(), creates a thread through ThreadStore.create(title) and calls Turns.wake: input UUID, str, RoutineOrigin(routine, trigger), output AcceptedResult.
  2. Turns.wake calls prepare_for_turn(), checks TurnPreparation.budgets and TurnPreparation.daily_cost through check_daily_budget, resolves the permission mode as today, and appends TurnStarted(message, model, permission_mode, origin).
  3. Turns._run calls LangGraphRunner.run(turn, emit) with a TurnRequest that now carries origin.
  4. The runner calls load_routines and picks the routine named in the origin (a missing routine fails the turn as not found), builds effective_budgets, and for a CodeStep calls gate.evaluate with the routine's mode: input GatePolicy, PermissionMode, ToolCall, Tool, Path, output GateDecision. Anything but allow fails the turn with the rule in the message.
  5. The runner emits ToolCall, calls Tool.ainvoke(arguments, ToolContext), and emits ToolResult.
  6. When the step returned None, the runner returns TurnOutcome(0, 0) and the turn service appends TurnCompleted(0, 0); the recap sees a turn with one tool call and writes a trace-only episode as today.
  7. Otherwise the runner builds HumanMessage(render_wake(origin, prompt, payload)), sets recursion_limit from the budgets on the run config, wraps graph.ainvoke in asyncio.timeout, and streams the model as today. Message deltas, tool calls and approvals follow the existing path, and the turn closes with TurnCompleted(input_tokens, output_tokens).

Flow: a turn meets its budgets

  1. Dispatcher routes thread.turn.start to Turns.start, which calls Turns.wake with UserOrigin().
  2. prepare_for_turn() reloads the manifest and the gate policy as today, and now also computes daily_cost(event_log.all_events(), price_map(manifest.prices), today): output TurnPreparation(model, default_mode, ceiling, budgets, daily_cost).
  3. check_daily_budget raises ModelUnpriced when usd_per_day is set and the turn's model, or any model that closed a turn today, is missing from the price map, and BudgetExceeded when DailyCost.spent has reached the limit. The dispatcher returns the ErrorEnvelope; nothing is appended.
  4. Otherwise TurnStarted is appended and the caller gets AcceptedResult.
  5. In LangGraphRunner._invoke the run config gets recursion_limit from Budgets.steps, and graph.ainvoke runs inside asyncio.timeout(Budgets.seconds). A GraphRecursionError or a TimeoutError becomes BudgetExceeded naming the budget.
  6. In _call_model, after the usage is added to ModelState.input_tokens and output_tokens, a total above Budgets.tokens raises BudgetExceeded. The exception leaves the graph the way ModelNoResponse does, so no partial step is checkpointed (ADR 0011).
  7. Turns._finish catches the CoreError and appends TurnFailed(code=BUDGET_EXCEEDED, message). The recap and the statistics treat it like any failed turn.

Flow: a user message while a routine runs

  1. The scheduler's fire has called Turns.wake with a RoutineOrigin; the routine turn is in Turns._running.
  2. The REPL sends ThreadTurnStartCommand(thread_id, message) for the user's thread.
  3. Turns.wake with a UserOrigin finds running_routine() and raises InstanceBusy, a retryable CoreError with code INSTANCE_BUSY naming the routine. Two user threads keep the per-thread rule and are not affected.
  4. The dispatcher returns ErrorEnvelope(code=INSTANCE_BUSY, retryable=True). run_repl prints the message once and retries the same command every second until it gets AcceptedResult, then renders the turn as today.
  5. A routine wake that finds any running turn raises the same error; the scheduler leaves the routine armed and awaits Turns.idle() before its next pass, so a due routine fires right after the user's turn closes.

  1. A routine with schedule fires when the fake clock passes its next occurrence; the new thread's turn.started carries RoutineOrigin(name, SCHEDULED), flow a scheduled fire, protects D1, D7.
  2. A routine whose last run in the log is older than its previous occurrence fires once at start() with CATCH_UP; one with catch_up: false or no history waits for the next occurrence, flow a scheduled fire, protects D10.
  3. A routine edited or disabled between passes changes the next pass without a restart, flow a scheduled fire, protects D4, D19.
  4. run.py returning None closes the turn with turn.completed(0, 0) and no model call; returning text puts that text inside the data block the model receives, flow a scheduled fire, protects D5, D6.
  5. A write code step under a routine mode of ask fails the turn with the gate rule in the message; under full-access it runs, flow a scheduled fire, protects D5, D14.
  6. A routine naming both run: and run.py, or a broken ROUTINE.md, is a warning in routine.list and never fires, flow a scheduled fire, protects D4.
  7. routine.run fires a disabled or unscheduled routine with MANUAL; an unknown name is not found; the method needs instance:admin, flow a scheduled fire, protects D17.

Open questions reference

Points the grilling did not settle, or settled in words the build had to refine. Each with the options on the table and the default the flows above assume. The agent building this stops and asks before acting on any of them.

  1. Which cron parser. Options: cronsim (no dependencies, handles DST, MIT), croniter (widely used, larger). Default: cronsim, pinned in the runtime dependencies.
  2. A code step the gate would ask about. The grilling parked approvals during routine runs (D14) and said a writing code step needs the routine's mode to allow it (D5). Options: fail the turn with the rule in the message; park the turn like a model tool call. Default: fail, because the step is the author's own code and the routine's mode is the author's answer.
  3. What a code step that returns None leaves behind. The grilling said "no wake". Options: a completed turn with zero tokens on the routine's thread; no record at all. Default: the completed turn, because the event log is the only run history (D10) and a fire that leaves nothing would catch up again at the next start.
  4. What kinby serve does with a running routine turn on shutdown. Options: interrupt it, as Ctrl+C in the REPL does; wait for it up to a grace period. Default: interrupt.
  5. What the REPL prints at startup. The grilling said "routines that ran since the last session". No session record exists. Options: each routine's last run from routine.list; runs since the last user-origin turn. Default: each routine's last run.

Glossary reference

Wake
The start of a turn by anything other than the user typing. Every wake carries an origin, which the thread records and the system prompt renders as a cue.
Origin
What started a turn: the user, a routine, or a signal.
Routine
A wake an instance owns and runs on a schedule: a prompt, and optionally the instance's own code step that runs first. Lives as a directory in the instance; its file is the source of truth.
Code step
A routine's own deterministic code, a tool never offered to the model, that runs before the model and may report "nothing new" so no model call is made.
Signal
An inbound stimulus from outside the instance, such as a webhook call or a received email, that wakes the agent without a schedule. Never called an event.
Budget
A ceiling an instance sets on one turn (steps, tokens, seconds) or on a UTC day (cost). Reaching it closes the turn as failed. Absent means unlimited; a routine may lower a budget, never raise it.
Turn
One user-to-agent cycle within a thread, from a message until the agent yields control. The unit of token attribution, checkpoint bracketing and eval cases.
Permission mode
A named preset of gate rules a thread runs under: read-only, ask, auto, or full-access. A thread, or a routine, may pin any mode up to the instance ceiling.
Event
One sequence-numbered record in a thread's durable history. The word keeps this meaning; inbound stimuli are signals.
