Blueprint

Permission gate

Stamped at dd10b9e: paths and symbols are true at this commit. Spec: issue #62. Design: wayfinder ticket #7, ADR 0014.

At a glance explanation

You get a gate that decides allow, ask, or deny for every tool call, driven by permissions.toml instead of the hardcoded write-flag check. Four permission modes are presets over per-tool rules, a thread pins its mode through the new thread.mode.set contract method, and a regex denylist catches known disasters even in full-access. The constraining decision is D2: modes are presets over per-tool rules, so the tool author's write flag stays a one-bit declaration and policy belongs entirely to the user.

Problem explanation

Today the runtime asks you to approve every write tool call and nothing else. You cannot tell kinby that edits in a trusted thread are fine while bash still asks. You cannot lock a thread to read-only over an untrusted workspace. Nothing stops rm -rf on the instance home or a force-push, even though permissions.toml sits in every instance directory. The file is scaffolded and unread. A turn parked on an approval also dies with the process, because the graph checkpointer is in memory.

Solution explanation

You write policy once in permissions.toml: a default mode, a ceiling, per-tool overrides, and bash pattern lists. Each thread runs under one of four modes. read-only lets the agent look, ask checks everything that writes, auto approves edits inside the workspace while bash still asks, and full-access frees everything except the denylist. You raise or lower a thread's mode from the REPL, never above the ceiling. When you deny a call, the agent hears "no" as a tool result and keeps working. When you restart, a parked turn is still there waiting for your answer.

Bird's-eye flow reference

The whole feature end to end. The event log and the subscription stream are unchanged and collapsed out of the figure.

  1. The REPL sends contract commands to core.dispatcher: thread.turn.start, thread.approval.respond, and the new thread.mode.set (D11).
  2. core.dispatcher checks the method's scope and routes the command to core.turns.
  3. core.turns resolves the thread's permission mode and hands run(TurnRequest) to core.turn_runner.
  4. instance.permissions reads permissions.toml at the turn boundary and merges it over kinby's shipped defaults (D12).
  5. instance.permissions hands the merged GatePolicy to core.gate.
  6. core.turn_runner calls evaluate on core.gate for every tool call and acts on the returned GateDecision (D2).
  7. core.turn_runner persists parked graph state in the SQLite checkpointer under .state/, so an answer can arrive after a restart (D7).

Ground-level flows reference

One subsection per flow named in the bird's-eye figure.

Flow: gated tool call

  1. _call_tools calls gate.evaluate per tool call: input GatePolicy, PermissionMode, ToolCall, output GateDecision.
  2. On allow the runner skips straight to step 6. On deny it skips to step 7. On ask it continues.
  3. _call_tools interrupts the graph with ApprovalRequested, as the placeholder already does.
  4. The runner emits ApprovalRequested carrying name, arguments, and the triggering rule. The turn parks. The SQLite checkpointer holds the graph state across restarts (D7).
  5. Turns.respond resumes the graph with the ApprovalDecision from thread.approval.respond.
  6. On approve, Tool.ainvoke runs with the call's arguments and the ToolContext, and the runner emits the ToolResult.
  7. On deny, the runner emits ToolResult(error=true) and the turn continues to the next model step (D4).

Flow: thread.mode.set

  1. The REPL sends thread.mode.set: input ThreadModeSetCommand with thread_id and mode.
  2. The dispatcher requires Scope.THREAD_ADMIN, the method's own scope, so a narrow client can never loosen anything (D11).
  3. Turns.set_mode calls load_permissions: output GatePolicy, which carries the ceiling.
  4. When the requested mode sits at or below the ceiling, Turns.set_mode appends a ModePinned event, so replay reproduces the mode and resuming the thread resumes its trust level. The result is AcceptedResult.
  5. When the requested mode exceeds the ceiling, the reply is ErrorEnvelope with code PERMISSION_DENIED (D1).
  6. An unpinned thread follows the instance default. Turns.start resolves the latest ModePinned event when it builds the TurnRequest.

Data shapes reference

Types the feature adds or changes. ApprovalRequested exists in kinby.contracts.models and gains three fields. EventType gains MODE_PINNED and Scope gains THREAD_ADMIN.

The wire enum for PermissionMode uses the mode names from D10 as values: read-only, ask, auto, full-access. The preset tables live in core.gate as data, one GatePolicy fragment per mode, and load_permissions lays the file's [tools] and [bash] entries over them (D12).

Testing reference

Seams
Two existing seams, none added. The contract dispatcher (build_dispatcher with fake runners) for thread.mode.set, scopes, and the ceiling. The turn runner (real graph, scripted model_factory) for gate decisions inside a turn. The gate's pure evaluation is exercised only through its callers (seam decision from the spec, resting on D2).
A good test here
Drives contract results and emitted events only. It never inspects GatePolicy internals, checkpointer rows, or graph state.
Prior art
tests/test_turns.py for dispatcher-seam tests with scripted runners. tests/test_run.py for runner-seam tests that stream a fake model through the real graph.

Cases

  1. A read-only tool runs without an approval in every mode, flow gated tool call, protects D2.
  2. In ask, a write tool call emits ApprovalRequested and parks the turn, flow gated tool call, protects D10.
  3. In auto, an edit inside the workspace runs without asking while bash still asks, flow gated tool call, protects D8 and D10.
  4. In auto, a write outside the workspace asks, flow gated tool call, protects D14.
  5. In full-access, a bash command matching a deny pattern returns an error tool result naming the rule, flow gated tool call, protects D9.
  6. A bash command matching an ask pattern asks in every mode above read-only, flow gated tool call, protects D9.
  7. A [tools] override changes one tool's tier without touching the preset, flow gated tool call, protects D2 and D12.
  8. A denied call returns ToolResult(error=true) and the turn continues to completion, flow gated tool call, protects D4.
  9. A parked turn resumes after a fresh runner starts over the same instance directory, flow gated tool call, protects D7.
  10. thread.mode.set without Scope.THREAD_ADMIN returns PERMISSION_DENIED, flow thread.mode.set, protects D11.
  11. thread.mode.set above the ceiling returns PERMISSION_DENIED, flow thread.mode.set, protects D1 and D13.
  12. A pinned mode survives thread resumption through event replay, flow thread.mode.set, protects D1.

Out of scope reference

  • Per-turn checkpoints as hidden git refs: ticket #60 (D5).
  • The agent modifying its own instance, tools or model: ticket #61 (D14).
  • Escalation as a tool parameter (D6).
  • OS-level sandboxing on local installs, container and pod provisioning (D3, ADR 0003).
  • MCP tool sources (out of v1 per wayfinder ticket #6) and memory facade writes (ticket #8).
  • A generated JSON Schema for permissions.toml: it follows whenever the kinby.toml schema treatment decided in ticket #6 lands. Neither exists at dd10b9e.

Open questions reference

Unsettled points. The agent building this stops and asks before acting on any of them.

  1. The exact shipped denylist regexes. The categories are fixed by D9: instance-home deletion, git history rewrites, force pushes. Options: a minimal three-pattern list, a broader curated list. Default: minimal, one commented pattern per disaster.
  2. How read-only is enforced: bind write tools and let the gate deny them, or exclude them from the model's bound tools for the turn. Options: gate-deny, unbind. Default: gate-deny, which keeps the tool snapshot semantics of ADR 0010 intact and teaches the model the boundary.
  3. How the gate learns a call's target paths for D14. Options: a fixed argument-name convention for the default tools, a path-parameter declaration on @tool. Default: a paths declaration on @tool naming the path-typed parameters, shipped filled-in for the default tools; a write tool without one asks in auto.
  4. The SQLite checkpointer packaging: the saver class, its dependency, and the file name under .state/. Default: LangGraph's async SQLite checkpointer as a new dependency, one database file per instance.

Glossary reference

gate
The check every tool call passes through before it runs: allow, ask, or deny.
sandbox
The isolation boundary around an instance: the container as the hard wall when deployed, the gate as the soft wall everywhere.
permission mode
A named preset of gate rules a thread runs under: read-only, ask, auto, or full-access.
denylist
Command patterns the gate refuses or escalates regardless of mode. A tripwire, not a wall.
approval
A user decision a live turn waits on. Requested as an event, answered through the contract.
tool
A native Python capability the model calls during a turn. Its write flag is the author's declaration the gate reads.
thread
One conversation with durable history. The unit a mode is pinned to.
turn
One user-to-agent cycle. Tools and policy are fixed at its start.
workspace
The directory holding the user's own work. The write bound in auto.
instance
One kinby deployment: a directory, and a container when deployed. The unit of trust and of sandboxing.
