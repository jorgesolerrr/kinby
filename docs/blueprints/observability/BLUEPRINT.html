Blueprint

Observability per instance

Stamped at 9719fef: paths and symbols are true at this commit. Decided in ticket #12, recorded in ADR 0026, built from spec #137.

At a glance explanation

You get a true cost for every turn, a gate verdict for every tool call, and a per-turn measure of how much of the work went into finding things in the workspace before acting. The event log widens to carry this: one event per model call, one gate decision per tool call, a write flag and a duration on the tool events, and a prompt version on the turn start. The decision that constrains everything is that the event log stays the only record: tracing stays local, statistics derive from the log, and nothing is written next to it.

Problem explanation

You run kinby stats after a week and the numbers lie in four ways. A turn that made five model calls and then hit a budget shows zero tokens, because turn.failed carries none, so your daily spend and the USD budget undercount every failure. You cannot see whether a tool rescan blew the prompt cache, because the runner reads only input_tokens and output_tokens and drops the cache counts. A deny by the gate is a sentence inside a tool.result, and nothing records an allow or the answer you gave to an approval. And you edited SYSTEM.md on Tuesday, but the rating trend cannot be split at Tuesday because no turn knows which prompt it ran under.

Behind those four sits the question you care about: is the agent learning your workspace? Memory records the trace of tools used in each episode, and recall is meant to hand that path back. If it works, the read, grep and glob calls a turn spends before its first edit should fall over time for the same repo. Today the log cannot show that. Tool calls carry no write flag, tool results carry no duration, and tokens are known only per turn, so the reasoning spent between reads cannot be told from the reasoning spent editing.

Solution explanation

Every turn records its model calls, its gate verdicts and its tool timings on the same thread it already writes to. A failed turn costs what it cost. kinby usage shows cached tokens per turn. The REPL prints a deny as a gate line. Each turn carries the version of the prompt it ran under, so you can split any trend at the day you changed SYSTEM.md.

On top of those events, turn metrics report navigation: read calls, their time, the distinct paths opened, how often a file was reopened, and the tokens spent before the first write. kinby stats averages navigation per day and per week over turns that wrote something. Watching that average fall for one workspace is how you see memory work. Nothing leaves the machine, and nothing new appears under .state/ except the fields on events already there.

Bird's-eye flow reference

Three writers append to the event log during a turn, and three readers derive everything from it. No writer keeps a second record. core.usage reads the log the same way core.stats does and is folded into that node.

  1. core.prompt renders the system prompt without the environment block and hashes it. Turns records the hash as prompt_version on turn.started (D5).
  2. LangGraphRunner appends model.completed after each model response (D3), then tool.call with the write flag (D9), tool.gated (D1) and tool.result with its duration (D8) for each tool call.
  3. Turns tallies the model.completed events it appends and writes the totals on turn.completed, turn.failed or turn.interrupted (D2).
  4. RecapWriter appends model.completed for the recap call and the split on memory.recapped (D3, D4).
  5. turn_metrics folds every event once into one TurnMetrics per closed turn, with the navigation block, denies, cache totals and time split (D10, D11).
  6. stats_buckets averages navigation over turns that wrote (D13). cli.main prints the table and writes stats.json.
  7. cli.repl renders the same stream live through thread.subscribe and prints a deny from tool.gated.

Module map reference

No module is new. The feature changes shapes in contracts and reads or writes them in eleven modules. The CLI reaches core.turns, core.usage and core.stats through the dispatcher; the figure draws the edges the feature changes and counts fan-in over the modules shown.

Interfaces

The calls and types other modules use after the change. Signatures use Python notation.

prompt_version(sections: Sequence[PromptSection]) -> str
core.prompt, new. Renders every section except ENVIRONMENT and returns the first twelve hex characters of its SHA-256. LangGraphRunner.prepare_for_turn calls it.
TurnPreparation.prompt_version: str
core.turns, new field. prepare_for_turn assembles the prompt sections once per turn and returns the version; Turns._wake copies it onto TurnStarted. The runner keeps the same sections for the turn.
TurnContext.emit(payload: Payload) -> Event
core.turns, unchanged signature. The closure in Turns._finish now adds every ModelCompleted it appends to the running turn's tally, so the closing event can carry totals on success, failure and interrupt.
token_cost(totals: TokenTotals, price: ModelPrice) -> float
core.pricing, changed. Takes the split instead of two ints. Cached tokens price at cache_read and cache_write when set, else at input.
turn_metrics(events, prices) -> TurnMetricsResult
core.turn_metrics, unchanged signature. Each record gains cache totals, model and tool time, denies, prompt version and a Navigation block. The result gains warnings for a per-call sum that differs from the closing total.
stats_buckets(records, by) -> list[StatsBucket]
core.stats, unchanged signature. Buckets gain cache totals, deny counts, time split and NavigationMeans.
render_event(event, stdout, stderr) -> None
cli.repl, unchanged signature. Prints a [tool.gated] line for a deny.

Ground-level flows reference

Three flows: a tool call through the gate, a model call and the closing totals, and the statistics fold that derives navigation. Participants are the functions from the module map.

Flow: a tool call through the gate

  1. _call_tools builds the ToolCall from the model's request and calls evaluate: input the gate policy, the thread's permission mode, the call and the selected tool; output GateDecision(action, rule).
  2. _call_tools emits ToolCall with write copied from the tool definition, for every requested call (D9). A call whose tool is not in the snapshot records write as true.
  3. When the action is ask, _call_tools emits ApprovalRequested and parks on interrupt. The user's answer resumes it as an ApprovalDecision.
  4. _call_tools emits ToolGated with the final action, the rule, and decided_by set to policy or user (D1).
  5. On allow, _run_tool times ainvoke and returns ToolResult with duration_ms (D8). _call_tools emits it.
  6. On deny, _call_tools emits the error ToolResult the model sees today, unchanged, with no duration.

Flow: a model call and the closing totals

  1. Turns._finish calls the runner with a TurnContext whose emit closure appends to the log and keeps a TokenTotals tally on the running turn.
  2. Per step, _call_model streams the model and folds the chunks; the last chunk carries usage_metadata with input_token_details.
  3. _call_model emits ModelCompleted: the exact model name, input and output tokens, cache_read_tokens and cache_creation_tokens from the details or zero, and the stream's duration (D3, D4). The token budget check reads the same numbers.
  4. The closure appends the event and adds its totals to the tally.
  5. When the run returns, _finish appends TurnCompleted with the tally. A no-work outcome still records zeros.
  6. When the run raises, _finish appends TurnFailed with the code, the message and the tally (D2). Turns.interrupt does the same for TurnInterrupted.
  7. RecapWriter._draft follows step 3 for the recap call and copies the split onto MemoryRecapped.

Flow: kinby stats derives navigation

  1. _show_stats sends StatsGetCommand through the contract client: input the optional time range and bucket size.
  2. get_stats calls turn_metrics over every stored event with the instance price map.
  3. Per turn, the fold counts ToolCall events by write, excluding the memory tools and skill; sums ToolResult.duration_ms by read and write; counts ToolGated denies by decided_by; collects distinct path arguments and repeat opens; and sums the ModelCompleted tokens that closed before the first ToolCall with write true, or all of them when the turn never wrote (D10, D11). It also sums ModelCompleted totals and adds a warning when they differ from the closing event.
  4. turn_metrics returns TurnMetricsResult: the records, the unpriced models, and the warnings.
  5. stats_buckets totals each bucket and computes NavigationMeans over the records whose write_calls is greater than zero (D13).
  6. get_stats returns StatsGetResult. _show_stats prints the navigation columns and writes every field to .state/stats.json.

Data shapes reference

Two figures: the event payloads in contracts, then the derived metrics and the price entry. Fields shown are the ones the feature adds or a decision cites.

Testing reference

Seams
The LangGraph runner with a scripted chat model, for everything the runner emits (D1, D3, D8, D9); turn_metrics over a hand-written event list, for everything derived (D10, D11, D13); the CLI through main and the REPL through run_repl, for what the user sees (D7). The event log is the seam between the first two, so neither test needs the other.
A good test here
Asserts the events a subscriber sees on the thread, the TurnMetrics a fold returns, or the text the CLI prints. Never the runner's tally, the fold's intermediate state, or a logger's handler list.
Prior art
tests/test_loop.py, tests/test_turns.py, tests/test_stats.py, tests/test_usage.py, tests/test_recap.py, tests/test_system_prompt.py, tests/test_cli.py, tests/test_repl.py.

Cases

  1. A turn with two model calls and one allowed tool call yields two model.completed events whose tokens sum to the turn.completed totals, a tool.call with write, a tool.gated allow by policy, and a tool.result with a duration, flow gate and model, protects D1, D3, D8, D9.
  2. A denylist hit yields tool.call, tool.gated deny by policy, and the error result, flow gate, protects D1.
  3. An approval the user refuses yields approval.requested, tool.gated deny by user, and the error result, flow gate, protects D1.
  4. A scripted usage with cache details lands on the call event and on the closing event, flow model, protects D4.
  5. A turn that raises on its second model call closes with turn.failed carrying the first call's tokens; an interrupt closes with the tally so far, flow model, protects D2.
  6. The recap call appends model.completed with the recap model and the split on memory.recapped, flow model, protects D3, D4.
  7. turn.started carries the same prompt_version on two dates under one SYSTEM.md, and a different one after an edit, flow model, protects D5.
  8. A hand-written turn with three reads, one write and two reads reports read calls 5, navigation read calls 3, and tokens before first write equal to the model calls before the write, flow stats, protects D10.
  9. A turn with reads only reports all reads as navigation and all tokens before first write, flow stats, protects D10.
  10. A turn that opens the same path twice reports one distinct path and one repeat open; memory and skill calls are not counted, flow stats, protects D10, D11.
  11. A per-call sum that differs from the closing total produces one warning and leaves the cost on the closing total, flow stats, protects D3.
  12. Events without the new fields validate and fold with zeros and None, flow stats, protects D2, D4.
  13. Cached tokens price at cache rates when set and at the input rate when not; the manifest accepts the keys and the schema lists them, flow stats, protects D4.
  14. Buckets average navigation over turns with writes only, flow stats, protects D13.
  15. kinby stats prints the navigation columns and writes them to stats.json; kinby usage shows the split; --verbose raises the level and creates nothing under .state/, flow stats, protects D7, D13.
  16. The REPL prints a deny from tool.gated and nothing for model.completed, flow gate, protects D1.

Out of scope reference

  • A navigation eval on a fixture workspace. Fog on the map next to coding-task evals; it needs the Docker sandbox.
  • Hosted tracing or an OpenTelemetry exporter. Rejected in D6 and ADR 0026.
  • A log file under .state/. Stderr is the process log (D7).
  • Bytes returned by tools or per-file read sizes. Counts, durations and paths carry the trend.
  • A dashboard. The JSON kinby stats writes is the seam, fixed in #10.
  • Changing evaluate in core.gate. The verdict is recorded where it is applied, in the runner.

Open questions reference

Points the grilling did not settle. The agent building this stops and asks before acting on any of them.

  1. The write flag for a call whose tool is not in the snapshot. Options: record true; record false. Default: true, so an unknown tool never counts as navigation.
  2. The shipped cache rates for anthropic:claude-sonnet-4-6 and openai:gpt-5. Options: take the providers' published rates at build time; ship none and rely on the fallback. Default: take the published rates and cite them in the price map's docstring.
  3. The length of prompt_version. Options: twelve hex characters; the full digest. Default: twelve.
  4. The commands that take --verbose. Options: run and serve only; every command. Default: run and serve.
  5. What the REPL's post-turn line shows. Options: add cached tokens and tool time to the existing line; a second line. Default: one line.

Glossary reference

Event
One sequence-numbered record in a thread's durable history.
Transcript store
The canonical record of every conversation, persisted as the event log.
Turn
One cycle of agent work within a thread, the unit of token attribution.
Model call
One request to a model during a turn, recorded as an event with its tokens and duration.
Token usage
The input and output tokens attributed to a turn, with cached tokens recorded as a split.
Gate
The check every tool call passes through before it runs: allow, ask, or deny.
Gate decision
The gate's final verdict on one tool call, recorded as an event with the rule and who decided.
Approval decision
The normalized answer to an approval: approve or deny.
Navigation
The read-only tool calls and model reasoning a turn spends locating what it needs in the workspace before acting.
Prompt version
A hash of the rendered system prompt without the environment block, recorded when a turn starts.
Environment block
The last prompt section: instance id, persona name, workspace path, main model, date.
Turn metrics
The derived record of one closed turn.
Instance statistics
UTC day or week totals derived from the event history through turn metrics.
Price map
Input, output and cache prices per million tokens, keyed by exact model name.
