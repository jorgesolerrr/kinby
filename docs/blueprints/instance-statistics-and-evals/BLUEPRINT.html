Blueprint

Instance statistics, turn rating, and the eval harness

Stamped at de30ea9: paths and symbols are true at this commit.

At a glance explanation

You get a per-instance table of how your kinby is doing, a good-or-bad prompt after each turn that feeds it, and an offline eval suite that gates the memory feeds. Everything is computed from the thread event log by one core function, turn_metrics; the REPL, kinby stats, and the Inspect AI scorer all read the same numbers. The decision that constrains the rest is that nothing is recorded twice: the rating is an event on the thread, the report is derived into .state/, and the evals never run in pytest or CI.

Problem explanation

You have run an instance for a few weeks. kinby usage prints tokens per turn and nothing else. You cannot tell how often the agent searched memory, which tools it leaned on, how many turns stopped at an approval, or how long a turn took. When an answer is bad there is nowhere to say so, and nothing you could later trace back. On the other side, the light graph feed shipped on the promise of expected-behavior checks (the three temporal questions, remember-then-recall, forget-stays-forgotten) that nobody has run. evals/ holds a .gitkeep, Inspect AI is not a dependency, and the memory ticket left the pass thresholds to this one.

Solution explanation

After a completed turn the REPL asks for a verdict, good or bad, with an optional reason, and enter skips. The verdict is a turn.rated event under the turn it judges, and any client can send one later through thread.turn.rate. kinby stats prints one row per day or week with tokens, cost, tool calls, memory calls, turns that consulted no memory, approvals, mean duration and the good-to-bad split, then writes the same result as stats.json into the state directory. Cost comes from a shipped price map you can override per model in kinby.toml. An unpriced model prints a warning and no number. Under evals/memory/ an Inspect AI task runs the memory question set against fixture instances in two arms, graph and transcript stuffing, and the feed gate reads the pair (correctness, memory tokens) off the log. I think the split matters more than any single number here. The rating is a trend for the person running the instance, the eval is a gate for the person building the next feed, and neither can stand in for the other.

Bird's-eye flow reference

One figure of the whole feature end to end. Boxes are modules or systems. Arrows carry the call or data that crosses. Decision ids lead the label where a decision picked the route.

  1. After a completed turn, run_repl asks for a verdict and calls thread.turn.rate (D3, D5).
  2. The dispatcher hands the command to rate_turn, which appends turn.rated under the turn id (D3, D4).
  3. kinby stats calls stats.get with the window and bucket size (D8).
  4. The handler reads every event from the log and calls turn_metrics with the price map (D1, D2).
  5. turn_metrics prices each turn through price_for; a model without a price yields cost none (D9).
  6. The CLI prints the buckets and writes the result as stats.json into the state directory (D8).
  7. Inspect AI hands each sample to the evals.memory task, which copies the fixture and drives turns through thread.turn.start with an adapter model factory (D11, D12).
  8. The task's scorer reads the copied instance's log through turn_metrics for memory tokens and the opened node, and grades the answer with a judge model (D13, D18).

Interfaces

The functions and types other modules call. Names match the file map and the figures.

turn_metrics(events: Iterable[Event], prices: PriceMap) -> tuple[TurnMetrics, ...]
One record per closed turn, in log order. Called by the stats.get handler, by usage_totals, and by the eval scorer (D2).
instance_statistics(turns: Sequence[TurnMetrics], window: UsageRange, by: Bucket) -> StatsGetResult
Filters the turns to the window, buckets them by UTC day or Monday-start week, and lists the unpriced models. Called by the stats.get handler.
estimate_tokens(text: str) -> int
Characters divided by four (D18). Used by turn_metrics for memory tool results and by the eval scorer for the profile section.
price_for(model: str, prices: PriceMap) -> Price | None
Exact match on provider:model. PriceMap is Mapping[str, Price]; SHIPPED_PRICES is the default and the manifest's prices overlays it (D9).
rate_turn(event_log: EventLog, command: ThreadTurnRateCommand) -> AcceptedResult
Raises NotFound for an unknown thread or turn, TurnOpen when the turn has no closing event, otherwise appends TurnRated (D3, D4). Registered by build_dispatcher whether or not a turn service exists.
build_dispatcher(state_dir, *, event_log=None, turns=None, prices=SHIPPED_PRICES) -> Dispatcher
Gains the price map so stats.get can cost turns. The CLI passes the manifest's overlay.
run_repl(client, thread_id, *, stdin, stdout, stderr, ask_rating: bool) -> int
When ask_rating is true, prompts after each completed turn and calls thread.turn.rate (D5). The CLI derives the flag from manifest.feedback.ask.
THREAD_TURN_RATE, STATS_GET
The two new contract methods, thread.turn.rate under Scope.THREAD_RATE and stats.get under Scope.INSTANCE_READ.
memory_recall(arm: Arm = Arm.GRAPH, judge: str) -> Task
The Inspect task in evals/memory/task.py. One sample per case directory; the arm decides whether the fixture is copied as is or stuffed (D14).
inspect_model_factory(model: str) -> ChatModel
The ModelFactory adapter in evals/memory/inspect_model.py: returns an InspectChatModel whose astream and bind_tools route to Inspect's active model (D12). Passed to both LangGraphRunner and RecapWriter.

Ground-level flows reference

One subsection per flow in the bird's-eye figure. Participants are the functions from the module map. Each figure is followed by the steps with the data shape at each hop.

Flow: rate a turn from the REPL

  1. _render_turn returns after turn.completed; a failed or interrupted turn skips the rest (D4).
  2. When ask_rating is true, _ask_rating prints the prompt and reads one line for the verdict and, on good or bad, one for the reason. Enter returns without a call (D5).
  3. run_repl calls thread.turn.rate: input ThreadTurnRateCommand.
  4. The dispatcher validates scope thread:rate and payload, then calls rate_turn.
  5. rate_turn reads the thread's events: output list[Event]. No thread or no turn raises NotFound.
  6. With a closing event under the turn id, it appends TurnRated: output Event, then AcceptedResult (D3).
  7. Without one it raises TurnOpen, which the dispatcher turns into an ErrorEnvelope with code TURN_OPEN.
  8. The REPL prints the error to stderr or nothing on success, and shows the next prompt. It ignores the turn.rated event on the subscription.

Flow: kinby stats

  1. main loads the selected instance and builds the dispatcher with manifest.prices overlaid on SHIPPED_PRICES (D9).
  2. It calls stats.get: input StatsGetCommand with since, until and by.
  3. The handler reads every event: output Iterator[Event].
  4. turn_metrics folds events by turn id: output tuple[TurnMetrics, ...]. For each closed turn it calls price_for with the turn's model and again with the recap model from memory.recapped (D19).
  5. instance_statistics keeps turns whose closing event falls in the window, buckets them, and lists models that priced as none: output StatsGetResult.
  6. main prints one row per bucket and the totals, prints one warning line naming the unpriced models when any, and writes the result's JSON to stats.json in the state directory (D8).

Flow: one eval sample under Inspect AI

  1. Inspect calls the solver with a Sample whose input names the case directory; the task parameter names the arm (D16 lets --model carry a list).
  2. The solver copies the fixture instance into a temporary directory. For the stuffing arm it deletes memory/graph/ and appends transcript.md to memory/profile.md (D14). It builds LangGraphRunner and RecapWriter with inspect_model_factory and passes them in a TurnConfig to build_dispatcher.
  3. For each turn in case.toml it calls thread.turn.start and waits on thread.subscribe for the closing event: input ThreadTurnStartCommand, output the turn's events.
  4. LangGraphRunner.run streams from InspectChatModel.astream, which converts the LangChain messages and bound tools, calls Inspect's active model, and converts ModelOutput back into AIMessageChunk with tool calls (D12).
  5. After the closing event the solver calls RecapWriter.drain so the remember-then-recall case sees the episode before the next turn.
  6. The solver returns a TaskState whose output is the last turn's assistant text and whose metadata holds the copied instance path.
  7. Inspect runs the scorers: model_graded_fact with the judge model, node_opened reading tool.call events for memory_open with the expected node, and memory_tokens from turn_metrics plus estimate_tokens on the profile (D13, D18).

Testing reference

Seams
One seam for rating and statistics: the dispatcher built by build_dispatcher with a scripted runner in TurnConfig, as the usage and turns tests already do (D1, D2). The REPL and the CLI are tested through their public entry points, run_repl and main, on top of the same dispatcher. The manifest is tested through load_instance. The evals are not tested in pytest (D17).
A good test here
Asserts what a subscriber sees on thread.subscribe, what stats.get and usage.get return, what kinby stats prints and writes, and what the REPL prints and sends. Never the bucket arithmetic through a private helper, never the queue in the recap writer.
Prior art
tests/test_usage.py (scripted runner, dispatcher, CLI usage view), tests/test_turns.py, tests/test_repl.py (string streams over a real dispatcher), tests/test_thread_cli.py, tests/test_instance_show.py, tests/test_schema.py.

Cases

  1. Rating a completed turn appends turn.rated under the turn id, seen on thread.subscribe; flow rate; protects D3.
  2. Rating a running turn returns TURN_OPEN; an unknown turn returns NOT_FOUND; flow rate; protects D4.
  3. Two ratings on one turn: stats.get reports the second; flow stats; protects D4.
  4. A scripted turn with two bash calls, one memory_search, one memory_open and one approval yields a TurnMetrics with those counts, memory_consulted true, and a duration from the two timestamps; flow stats; protects D7, D20.
  5. A turn with no memory tool call counts under turns_without_memory; flow stats; protects D7.
  6. Recap tokens fold into the turn's totals and price at the recap model on the marker; flow stats; protects D19.
  7. A model absent from the price map yields cost_usd none and appears in unpriced_models; a manifest override changes the cost; flow stats; protects D9.
  8. Turns on two days bucket into two rows by day and one by week; since and until exclude turns outside them; flow stats; protects D8.
  9. usage.get returns the same result as before for the existing usage cases; flow stats; protects D2.
  10. kinby stats prints a row per bucket and writes stats.json that parses back into StatsGetResult; flow stats; protects D8.
  11. The REPL prompts after a completed turn, sends good with a reason on g then a line, skips on enter, never prompts under off, never prompts after a failed turn; flow rate; protects D5.
  12. kinby init writes [feedback]; a manifest with an unknown key under [feedback] or [prices] fails to load; the schema names both; flow rate, stats; protects D5, D9.

Out of scope reference

  • A web dashboard. Ruled out by the map; stats.json is what it would read.
  • A gate decision event and any denial statistic. Observability (#12).
  • Coding-task evals with a workspace and Docker sandbox; replay-from-thread eval cases. Fog on the map.
  • Which models to compare and how to publish results. Cross-model comparison protocol (#93).
  • A rating scale beyond good and bad; rating anything but a turn.
  • Hosted tracing. The event log stays the source of truth; #12 decides whether traces also go elsewhere.

Open questions reference

Points the grilling did not settle. The agent building this stops and asks before acting on any of them.

  1. Which models the shipped price map covers at first. Options: only the models named in examples/instances/; every model a provider page lists. Default: the example models, prices copied from the provider pages on the build date.
  2. The judge model for model_graded_fact. Options: a fixed task default; the sample's own model. Default: a fixed default in the task, overridable by a task parameter, never the model under test.
  3. Whether kinby instance show prints the feedback policy and the price overrides. Options: yes as two more lines; no. Default: no, until someone asks.
  4. The Inspect AI version pin. Options: a minimum bound; an exact pin. Default: a minimum bound at the release current on the build date, like every other dependency here.

Glossary reference

Turn rating
The user's verdict on one turn: good or bad, with an optional reason. Recorded on the thread next to the turn it rates.
Instance statistics
Per-turn measures of one instance aggregated over a time window, with trends. Derived from the transcript store, never recorded separately.
Eval
An offline, scored run of one or more turns against reference answers, under a named model. Paid for and run on demand.
Feed gate
The eval thresholds a feed must pass before kinby builds the next one.
Turn
One user-to-agent cycle within a thread. The unit of token attribution and eval cases.
Event
One sequence-numbered record in a thread's durable history. Replaying it reproduces a thread.
Transcript store
The canonical record of every conversation with the agent.
Feed
One source of memory behind the memory facade. Each feed must pass its evals before kinby adds the next one.
