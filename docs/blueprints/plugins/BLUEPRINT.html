Plugins: tools, skills, system prompt assembly

Stamped at 6aa4a52: paths and symbols are true at this commit. Source: grilling on #6, build spec #43, slice tickets #44–#51. #44, #45, and #46 are merged; #47–#51 are open. Where the code exists it is the second source of truth. Known defect at this commit: src/kinby/core/turn_runner.py:158-160 holds a leftover async for header from the #54 merge, so the file does not parse. The figures describe the intended code with those three lines removed.

At a glance explanation

You drop a Python file in your instance's tools/, a SKILL.md folder in skills/, or edit SYSTEM.md, and the next turn uses it. Tools come from the instance directory and from installed packages through one registry that rescans at every turn start. The system prompt is a fixed sequence of sections with the volatile environment block last. The decision that shapes the rest is D4: no watcher, no reload command, the turn boundary is the only moment the tool set changes. That keeps the provider's prompt cache valid across turns and keeps the runtime free of background tasks.

Problem explanation

Before this feature a turn ran the model with no tools and a bare user message. kinby init wrote tools/, skills/, and SYSTEM.md, and nothing read them. You could not give your teammate a capability, tell it how to behave, or see what it would load before spending a model call.

Solution explanation

Every turn, the runner reloads the manifest, rescans tools/, reads the skills, and assembles the system prompt. The model can call your tools. A write tool parks the turn on an approval request that you answer from the REPL. kinby instance show prints the tools, skills, and prompt sections a turn would use, with any load warnings. A generated JSON Schema for kinby.toml lives in the repo. At 6aa4a52 the first two sentences are true for instance tools and the prompt; the default package, skills, write approval, the show listing, and the schema are the open tickets.

Bird's-eye flow reference

Files on disk and installed packages become the tools, skills, and system prompt of one turn. kinby instance show reads through the same loaders. Boxes are the functions other modules call. Arrows carry what crosses.

  1. ToolRegistry.refresh reads the kinby.tools entry-point group once per session and takes every Tool each entry resolves to. The default package is one of those entries when [tools] defaults is true (D3, #47).
  2. The same refresh computes the signature of tools/*.py, executes each changed file as a fresh module, and collects every Tool the module exposes (D3, D4). An instance tool shadows a same-named entry-point tool.
  3. load_skills reads skills/*/SKILL.md from the instance and from each workspace convention skill directory, instance first (D8, #49).
  4. refresh returns the name-sorted ToolSnapshot plus zero or more Warning payloads to LangGraphRunner._invoke (D4, D5).
  5. assemble_system_prompt turns the skill list into the catalogue section and returns the PromptSection tuple in D9 order (D8, D9).
  6. LangGraphRunner receives the sections and joins them into one system message with render_system_prompt.
  7. During the turn, each tool execution emits tool.call and tool.result, each warning emits warning, and a write tool emits approval.requested and parks (D6, D15).
  8. _print_instance calls the three loaders and prints their results after the existing manifest lines (D12, #50).

Ground-level flows reference

Three flows: a turn that calls a non-write tool (built), a write tool parking the turn (#48), and kinby instance show (#50). Participants are the functions from the module map.

Flow: turn start with a tool call

  1. Turns.start calls run(turn: TurnRequest, emit), and run calls _invoke. _invoke calls ToolRegistry.refresh() (D4): output the ToolSnapshot for this turn and zero or more Warning.
  2. For each warning, _invoke calls emit(Warning(sources, message)): output the appended Event (D5).
  3. _invoke calls assemble_system_prompt(instance, skills, today): output tuple[PromptSection, ...], joined by render_system_prompt into one SystemMessage (D9). Today the call has no skills argument; #49 adds it.
  4. The model node binds the snapshot's runnables and streams [system, user]. Each chunk with text emits MessageDelta as before. Output: one AIMessageChunk with tool_calls and usage.
  5. _after_model routes to the tools node while the response carries tool calls (D14). _call_tools receives ModelState and the ModelContext holding the snapshot and the ToolContext.
  6. For each call, _call_tools emits ToolCall(call_id, name, arguments), looks the name up with tools.get(name), and calls Tool.ainvoke(arguments, tool_context) (D7). An unknown name or a raised exception becomes ToolResult(error=True).
  7. _call_tools emits ToolResult(call_id, name, output, error) and appends a ToolMessage with the matching status (D15).
  8. The graph returns to the model node, which streams [system, *messages] without repeating the user message (D19). The loop ends at the first response with no tool calls.
  9. _invoke returns TurnOutcome(input_tokens, output_tokens) summed across every model call in the turn.

Flow: write tool approval

  1. _call_tools finds tool.write true (D6). It emits ApprovalRequested(approval_id, request) whose request names the tool and its arguments, then calls LangGraph interrupt(), which parks the graph.
  2. _invoke returns ParkedTurn to Turns._finish, which leaves the thread parked as ADR 0009 describes.
  3. You answer at the REPL. run_repl sends thread.approval.respond with ThreadApprovalRespondCommand(thread_id, approval_id, answer) through the dispatcher to Turns.respond.
  4. Turns.respond calls resume(turn, answer, emit). The runner resumes the graph with Command(resume=answer), and _call_tools continues from the interrupt.
  5. When the answer is yes, _call_tools emits ToolCall, runs Tool.ainvoke, and emits ToolResult. Any other answer emits ToolResult(output="denied by user", error=True).
  6. The ToolMessage goes back to the model node, and the turn continues to TurnOutcome as in Flow: turn start.

Flow: instance show

  1. _print_instance builds ToolRegistry(instance.path, defaults=manifest.tools.defaults) from the loaded Instance (D3).
  2. It calls refresh() once: output the ToolSnapshot and the warnings.
  3. It calls load_skills(instance.path, manifest.workspace.conventions.skills): output tuple[Skill, ...] (D8).
  4. It calls assemble_system_prompt(instance, skills, today): output tuple[PromptSection, ...] (D9).
  5. It prints, after the existing lines: tools: (name, write or read, source), skills: (name, source), prompt sections: (name, source, character count), warnings: (sources, message) (D12).

Data shapes reference

Plugin records are frozen dataclasses in src/kinby/plugins/ and src/kinby/core/prompt.py. Tools is the manifest's new [tools] table in src/kinby/instance/dataclasses.py, declared by RawTools in manifest.py.

The event payloads are ContractModels with extra="forbid" in src/kinby/contracts/models.py. ApprovalRequested is unchanged; its request string names the tool and arguments once #48 lands.

REPL rendering in _render_event: ToolCall writes [tool.call] name {arguments} with sorted keys; ToolResult writes [tool.result] name (ok|error): output; Warning writes [warning] sources: message to stderr.

Open questions reference

Points the grilling did not settle. The agent building this stops and asks before acting on any of them.

  1. A parked write tool across a restart. ADR 0009 resumes placeholder approvals from the event log by re-running the turn. A write tool parks mid-graph, and InMemorySaver loses that state on restart. Options: add a persistent checkpointer in .state/ now; fail resume after a restart with a clear NO_ACTIVE_TURN-style error and let #7 add persistence. Default: the second; keep the dependency out until the gate ticket decides the checkpointer.
  2. Default bash working directory and timeout. Workspace path as cwd is settled by D7. Timeout and output cap are not. Options: constants in plugins.defaults.shell; keys on the [tools] table. Default: 120 s and 30k characters as constants in plugins.defaults.shell.
  3. Entry points re-read. D4 reads them once per session. A package installed while kinby run is open appears next session. Options: leave it and document it in the tool-author page; re-read the group at every refresh. Default: leave it.
  4. Catalogue text. D8 fixes what the catalogue holds, not its wording. Options: one line per skill, - name: description; a short heading plus that list. Default: the heading plus the list, so the model knows to call the skill tool.

Glossary reference

Plugin
Anything an instance loads beyond the core: a tool or a skill, from the instance directory or from an installed package. The workspace never supplies plugins.
Tool
A native Python capability the model can call during a turn. Every tool declares whether it writes. Tools present at the start of a turn are the tools for that turn.
Tool registry
The instance-owned collection of tools available to turns. It keeps the last valid set when a tool file cannot load.
Tool snapshot
The fixed, name-sorted set of tools for one turn. The model and tool calls use the same snapshot for the whole turn.
Skill
A markdown instruction set the model reads on demand. Skills are listed to the model by name and description; the body is fetched only when the model asks for it.
Behavior prompt
The instance's own instructions to the model (SYSTEM.md). One of the sources assembled into the system prompt.
System prompt
The single system message assembled for each turn from an ordered set of prompt sections.
Prompt section
One named, attributable part of the system prompt. Missing file-backed sections are omitted.
Turn
One user-to-agent cycle within a thread. The moment the tool set may change.
Approval
A user decision a live turn waits on before it continues. Requested as an event; answered through the contract.
Event
One sequence-numbered record emitted while a turn runs.
