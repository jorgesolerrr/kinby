Runtime seam: contracts, dispatcher, event stream

Stamped at 6aa4a52: paths and symbols are true at this commit. Source: grilling on #5, build spec #28, slice tickets #30–#35, then #38–#54 which built on the seam. The code is the second source of truth. Known defect at this commit: src/kinby/core/turn_runner.py:158-160 holds a leftover async for header from the #54 merge, so the file does not parse. The figures describe the intended code with those three lines removed.

At a glance explanation

You chat with your instance from kinby run, and every command the REPL sends crosses one typed boundary: pydantic models in kinby.contracts, a name-routed Dispatcher that checks scope and validates before a handler runs, and an append-only event log that is the transcript. Commands return an AcceptedResult at once. All output arrives on thread.subscribe, which replays stored events past a sequence number and then stays live. The decision that shapes everything else is D2: events carry a gap-free per-thread sequence, so reconnect, replay, restart, and a future server are the same code path.

Problem explanation

Before this feature kinby run resolved the instance and stopped with "The agent loop is not yet available." You could not chat. A second client is coming (a server that fronts the same core), and a session object with hand-matched methods would force a second API design. Without a sequence-numbered record, a client that drops mid-turn cannot recover what it missed, a parked approval dies with the process, and evals cannot replay a thread.

Solution explanation

kinby run opens a thread and a prompt. Each line you type becomes thread.turn.start. The receipt comes back immediately and the model's reply streams onto your terminal from the subscription, tool calls and results as one line each. Ctrl+C during a reply sends thread.turn.interrupt, prints (interrupted), and gives the prompt back. A second subscriber, or a restarted process, replays the thread event for event. A turn parked on an approval survives a restart and resumes when thread.approval.respond arrives. kinby usage prints token totals folded from the same events. Every one of these calls goes through the dispatcher, so putting a socket in front of it later changes nothing behind it.

Bird's-eye flow reference

A line typed at the REPL crosses the contract, becomes a turn, lands as sequence-numbered events in the instance event log, and returns to the REPL through the one subscription. Boxes are the modules other modules call. Arrows carry what crosses.

  1. run_repl reads a line and calls client.call(THREAD_TURN_START, ThreadTurnStartCommand(thread_id, message)). The session subscription, opened once at start, is already consuming events in the same coroutine's _render_turn loop.
  2. ContractClient.call dumps the command and calls Dispatcher.dispatch("thread.turn.start", payload, scopes) with the CLI's four scopes. It parses the generic result into AcceptedResult or ErrorEnvelope (D20).
  3. Dispatcher.dispatch finds the route, checks thread:operate is among the scopes, validates the payload into ThreadTurnStartCommand, and calls Turns.start. Any failure on this path comes back as an ErrorEnvelope (D5, D6).
  4. Turns.start checks the thread exists and is not busy (D10), resolves the model through prepare_for_turn (D22), appends TurnStarted, and returns AcceptedResult with that event's sequence (D3).
  5. In the same call, Turns.start spawns an asyncio task that runs LangGraphRunner.run(turn, emit) inside the terminal-event wrapper Turns._finish.
  6. LangGraphRunner.run assembles the system prompt, refreshes the tool snapshot, emits any Warning, and streams the chat model. Every chunk becomes emit(MessageDelta), every tool call emit(ToolCall) and emit(ToolResult) (D15, D23).
  7. EventLog.append assigns the next sequence for the thread under its lock, writes one line to events.jsonl (D11), and puts the Event on every live subscriber queue.
  8. The thread.subscribe generator yields the event and run_repl renders it: deltas inline, tool lines, warnings to stderr, and a terminal event as the cue to prompt again. When the runner returns, Turns._finish appends TurnCompleted with the token counts.

Ground-level flows reference

Four flows: the REPL starts a turn, the turn streams, a subscriber replays, and one turn's lifecycle. Participants are the functions from the module map.

Flow: turn start

  1. run_repl opens the session subscription: input ThreadSubscribeCommand(thread_id, after_sequence=0), output an async generator of Event | ErrorEnvelope. It stays open inside aclosing for the whole session.
  2. ContractClient.subscribe dumps the command and calls Dispatcher.subscribe("thread.subscribe", payload, scopes).
  3. Dispatcher.subscribe admits the call (thread:read, ThreadSubscribeCommand) and calls EventLog.subscribe(thread_id, 0). An unknown thread yields an empty live stream (open question 1).
  4. You type a line. run_repl calls client.call(THREAD_TURN_START, ThreadTurnStartCommand(thread_id, message)): output AcceptedResult | ErrorEnvelope.
  5. ContractClient.call calls Dispatcher.dispatch("thread.turn.start", payload, scopes).
  6. Dispatcher.dispatch checks the route exists, then thread:operate, then validates into ThreadTurnStartCommand. Each failure returns its ErrorEnvelope without calling the handler (D5, D6).
  7. Dispatcher.dispatch calls Turns.start(command).
  8. Turns.start checks ThreadStore.exists (else ThreadNotFound), then reads EventLog.stored(thread_id). A last event of approval.requested, a live task, or a concurrent start in _starting raises ThreadBusy (D10).
  9. Turns.start calls prepare_for_turn(), which re-reads the manifest and returns the model name (D22). Output: a TurnRequest(thread_id, uuid4(), message, model).
  10. Turns.start calls EventLog.append(thread_id, turn_id, TurnStarted(message, model)): output the Event whose sequence is the sequence at accept.
  11. Turns.start creates an asyncio task that runs _finish(turn), the wrapper around runner.run that appends the terminal event (see Flow: turn stream). No reply is awaited. It returns AcceptedResult(thread_id, turn_id, sequence) (D3).
  12. Dispatcher.dispatch returns the result. ContractClient.call narrows it to AcceptedResult | ErrorEnvelope. run_repl prints an envelope to stderr and otherwise waits for events.

Flow: turn stream

  1. LangGraphRunner.run calls assemble_system_prompt(instance, today) and ToolRegistry.refresh(). Every Warning the refresh returns is emitted as an event before the model is called (D15, D23).
  2. The graph's model node calls ChatModel.astream with the system message, the checkpointed messages, and the user message. The user message is added to the state together with the reply, so a failed call cannot checkpoint it (ADR 0011).
  3. For each chunk with text, _call_model calls emit(MessageDelta(text)). emit is the guarded closure Turns._finish built: input a Payload, output the appended Event.
  4. The guard raises TurnInterruptedError when the turn is no longer the running one or was interrupted (D16). Otherwise it calls EventLog.append(thread_id, turn_id, payload).
  5. EventLog.append puts the Event on every live subscriber queue for the thread. The session subscription yields it, and _render_turn writes text without a newline.
  6. When the reply carries tool calls, the tools node emits ToolCall and ToolResult per call and the graph returns to model. The REPL prints [tool.call] name {…} and [tool.result] name (ok|error): output.
  7. run returns TurnOutcome(input_tokens, output_tokens) accumulated from usage_metadata to Turns._finish.
  8. Turns._finish appends TurnCompleted(input_tokens, output_tokens). A CoreError from the runner becomes TurnFailed(code, message). Any other exception becomes TurnFailed(INTERNAL, "The model turn failed unexpectedly."). A ParkedTurn appends nothing: approval.requested was already emitted (see Flow: turn lifecycle).
  9. The subscription yields the terminal event. _render_turn returns and run_repl shows the prompt.

Flow: replay

  1. A ContractClient calls subscribe(THREAD_SUBSCRIBE, ThreadSubscribeCommand(thread_id, after_sequence=k)). k is 0 for a full replay, or the last sequence a dropped client saw.
  2. Dispatcher.subscribe checks thread:read and validates the command. On failure it yields one ErrorEnvelope and returns.
  3. The route handler calls EventLog.subscribe(thread_id, k).
  4. Under the log's lock, EventLog reads events.jsonl, keeps the lines whose thread_id matches and whose sequence > k, and registers an asyncio.Queue for live events. Snapshot and registration under one lock make the handoff exact: no event is missed and none is delivered twice (ADR 0006).
  5. The stored events come back as a list in file order, which is sequence order.
  6. The generator yields each stored Event. Dispatcher.subscribe passes each through, and ContractClient.subscribe narrows it to Event | ErrorEnvelope.
  7. The generator awaits the queue. Each event appended after the snapshot is yielded as it lands, still filtered by sequence > k.
  8. When the client closes the generator, aclosing runs the finally that removes the queue.

Flow: turn lifecycle

  1. turn.start → Running: Turns.start appends turn.started and spawns the task. The thread is busy while its id is in _starting, while its task is not done, or while its last event is approval.requested (D10).
  2. Running → Completed: the runner returns TurnOutcome. Turns._finish appends turn.completed with the token counts.
  3. Running → Failed: the runner raises. Turns._finish appends turn.failed with the CoreError code, or INTERNAL for anything else.
  4. Running → Interrupted: Turns.interrupt marks the running entry interrupted, cancels the task, appends turn.interrupted itself, and drops the entry. A runner still cleaning up cannot emit: the guard raises TurnInterruptedError (D16, ADR 0008).
  5. Running → WaitingApproval: the runner emits approval.requested and returns ParkedTurn. Today the approval_hook does this before the graph runs. No task stays alive. The thread's last event is non-terminal, which is the whole definition of parked, so a restart sees the same state (D17).
  6. WaitingApproval → Running: Turns.respond matches approval_id against the last event (else ApprovalNotFound), rebuilds the TurnRequest from the stored turn.started (else InvalidParkedTurn), spawns a task around runner.resume(turn, answer, emit), and returns AcceptedResult with the approval.requested sequence. It appends no event.
  7. WaitingApproval → Interrupted: Turns.interrupt with no task alive finds the pending approval and appends turn.interrupted directly.
  8. Any terminal state frees the thread: the next turn.start is accepted.

Seams
Two, plus one unit seam. First, build_dispatcher(tmp_path, turns=TurnConfig(fixed_model_name, ScriptedRunner())): the boundary every client crosses (D1), so a test here proves the contract, the scopes, the envelope, the busy guard, and the event log together with no model in the loop. The scripted runner emits a fixed list of payloads and can raise, park, wait on an asyncio.Event, or suppress cancellation. Second, run_repl(client, thread_id, stdin=StringIO(...), stdout=StringIO(), stderr=StringIO()) over that same dispatcher, which proves rendering and prompt discipline without a pty. LangGraphRunner is tested on its own with a fake ChatModel that yields AIMessageChunks. The provider call is not tested.
A good test here
Drive one or two contract calls, then assert on the events read back through thread.subscribe(after_sequence=0) and on the returned models. Never assert on task internals, queue sizes, or file layout. A test that survives replacing events.jsonl with SQLite is at the right altitude.
Prior art
tests/test_instance_show.py set the CLI pattern (main([...]) with capsys). tests/test_threads.py set the dispatcher pattern. Every test is synchronous and drives async code with asyncio.run. There is no conftest.py.

Cases

  1. A turn started through thread.turn.start streams turn.started, its deltas, and turn.completed in that order, and a rebuilt dispatcher replays them event for event, flow turn stream and replay, protects D2 and D3.
  2. Sequences stay gap-free after an EventLog restart, and a subscriber joining after sequence k receives k+1 onward once, then live events, flow replay, protects D2 and D11.
  3. thread.turn.start while a turn is live, or while a second start is being recorded, returns THREAD_BUSY with retryable=true; after the terminal event a new turn is accepted, flow turn lifecycle, protects D10.
  4. thread.turn.interrupt during a live turn ends the stream with turn.interrupted even when the runner suppresses cancellation; with no live turn it returns NO_ACTIVE_TURN, flow turn lifecycle, protects D16.
  5. A runner that raises ends the stream with turn.failed carrying the CoreError code, flow turn stream, protects D6.
  6. A runner that parks emits approval.requested; a rebuilt dispatcher on the same state_dir refuses a new start, accepts thread.approval.respond, and streams to turn.completed; an unknown approval_id returns NOT_FOUND; an interrupt while parked appends turn.interrupted, flow turn lifecycle, protects D17.
  7. A caller without the route's scope is refused before the payload is validated, for thread.subscribe and usage.get; an unknown method returns NOT_FOUND; a handler that raises returns INTERNAL, flow turn start, protects D5 and D6.
  8. usage.get after two turns on two threads reports totals per thread and per turn equal to the recorded turn.completed payloads, filtered by an inclusive range; kinby usage rejects a naive timestamp, protects D18.
  9. run_repl renders deltas inline, prints the prompt only after the terminal event, prints [tool.call], [tool.result], and [warning] lines, and turns SIGINT into thread.turn.interrupt, flow turn stream, protects D16 and D23.
  10. LangGraphRunner re-reads the model between turns, applies the session override, keeps a failed call out of checkpoint history, and parks then resumes through the approval hook, flow turn stream, protects D13, D17, and D22.
  11. main(["run", dir]) with empty stdin prints the instance summary, creates a thread, and exits 0, protects D7 and D21.

Open questions reference

Points the code does not settle. The agent building on this seam stops and asks before acting on any of them. Of the seven questions in the first draft, the checkpointer backend, provider packages, busy-while-parked, and approval lookup are closed in D13, D10, and D17.

  1. thread.subscribe on an unknown thread. The handler yields an empty live stream. Options: keep; return NOT_FOUND through ThreadStore.exists before the handler runs. Default: NOT_FOUND, for symmetry with turn.start.
  2. Sequence assignment cost. EventLog.append computes the next sequence as len(stored(thread_id)) + 1, re-reading the whole file under the lock on every append. Options: an in-memory {thread_id: last_sequence} warmed at startup; one file per thread; SQLite. Default: the cache, kept behind the same append signature.
  3. Ctrl+C at the prompt. _InterruptOnSigint is active only during a turn. At the prompt, SIGINT raises KeyboardInterrupt out of asyncio.run. Options: exit 0; ignore; require a second Ctrl+C. Default: exit 0, matching EOF.
  4. Answering an approval from the REPL. _render_event has no arm for ApprovalRequested, so a parked turn shows nothing and run_repl keeps waiting for a terminal event. Options: print request, read one line, send thread.approval.respond; leave until #7 fixes the shape. Default: leave until #7, since the placeholder hook has no producer outside tests.
  5. A process that dies mid-turn. The last stored event is turn.started or a delta with no terminal event. On restart Turns.start sees no pending approval and no task, so the thread is free, but the transcript never closes that turn. Options: append turn.failed(INTERNAL) for every open turn at build_dispatcher; leave. Default: leave, and revisit when evals replay threads.
  6. Several pending approvals per turn. Turns.respond matches approval_id against the thread's last event only. Options: keep; store pending approvals in the checkpointer state and query it. Default: keep; revisit with #7.

Glossary reference

Thread
One conversation with its own durable history. Survives across sessions. What memory distills from and what evals replay.
Session
One run of the agent loop against a thread, from kinby run to exit. The unit a server wraps.
Turn
One user-to-agent cycle within a thread, from a user message until the agent yields control. The unit of token attribution and checkpoint bracketing.
Turn interruption
A user's request to stop the active turn before it completes.
Turn runner
The part of the runtime that produces the agent's response and the turn's events. TurnRunner in code, LangGraphRunner in production.
Approval
A user decision a live turn waits on before it continues. Requested as an event, answered through the contract. A parked turn stays live until answered or interrupted.
Contract
The typed set of commands and subscriptions every client uses to drive a session. Clients import contracts, never core.
Event
One sequence-numbered record emitted while a turn runs. What clients subscribe to and what the transcript store persists.
Scope
A named permission a contract command requires of its caller.
Token usage
The input and output tokens attributed to a turn, rolled up per thread. A usage range includes completed turns whose timestamp falls on or between its bounds.
Transcript store
The canonical record of every conversation. Here, the event log.
Tool snapshot
The fixed, name-sorted set of tools for one turn.
