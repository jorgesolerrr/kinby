# Recap runs after the turn as an event-marked reactor

Ticket #9 chose to run the recap as a runtime-owned background task started after the turn's closing event is appended, not as a node in the LangGraph turn graph, because the turn ends when the model yields and a recap node would delay `turn.completed` and put memory writing inside the turn's checkpoint history (ADR 0011). The recap records its completion as a `memory.recapped` event on the thread's log, carrying the turn id, the node written (or none) and its token totals, so the event log alone says which turns are covered: a startup sweep recaps every closed turn without a later `memory.recapped`, which handles both a crash between turn and recap and a failed recap with one mechanism. A cursor in episode frontmatter was rejected because it would make the graph, a derived artifact, the authority on what the transcript store has been distilled into. The next turn never waits on the recap: the thread's own history already reaches the model through the graph checkpoint, so the previous turn's episode adds nothing to it.
