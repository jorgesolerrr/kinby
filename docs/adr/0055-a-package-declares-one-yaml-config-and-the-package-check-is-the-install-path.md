# A package declares one YAML config, and the package check is the install path

A **package** may declare one instance-owned config file, `package.yaml`, through a validator: a `PackageConfig` model that forbids unknown keys. Core reads the file with `yaml.safe_load` and validates it at initialization, at boot, in the candidate image before an update stops the container, and at the start of every code-step run. A code step receives the result on `ToolContext`. Each run reads the file again, so an edit applies at the next run without a restart. A missing or invalid file fails with the validator's message and the path. Core never falls back to defaults, because a default the user did not choose is a setting the user cannot see. A field typed `SecretName` holds an environment variable name, and validation checks it against the package's declared required secrets, so the file never holds a secret value. Routine `arguments` stay available, but package settings belong in `package.yaml`: one file the user edits, not one JSON line per routine. YAML costs one runtime dependency, `pyyaml`. We took it because the file is written by hand and carries a comment for each setting, which JSON cannot.

`kinby package check <id>` runs kinby's own install path against an installed package and reports every failure at once. It resolves the entry point and its distribution metadata, checks that the template ships in that distribution, and initializes the template into a temporary directory. There it loads the manifest, routines and code steps. It validates the template's `package.yaml`, resolves the package's skills and their linked companion files, and checks secret declarations and declared `executables` on `PATH`. It runs no routine, calls no model, and needs no network. Signal routines load against placeholder values for declared secrets, because the check holds no secrets.

The hub's candidate check, `python -m kinby.packages <id> [<instance-directory>]`, runs the same code inside the prepared image. On an update, the hub mounts that instance's `package.yaml` read-only, passes the directory that contains it, and runs the check with no network. The rest of the instance, including `.env`, stays unmounted. Any failure stops the update before the running container is touched. CI and the hub run one check, so they cannot disagree about whether a package installs.

Decision agreed during [Give packages a validated package.yaml and a package check](https://github.com/jorgesolerrr/kinby/issues/268), under [ADR 0041](0041-package-initialization-uses-declared-inputs.md) and [ADR 0043](0043-package-updates-validate-existing-configuration.md).
