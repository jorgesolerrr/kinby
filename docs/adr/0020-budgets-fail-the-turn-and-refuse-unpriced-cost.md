# Budgets fail the turn and refuse unpriced cost

Ticket #11 chose four budgets with one mechanism each, declared in a `[budgets]` table of `kinby.toml` and applied to user turns and routine runs alike: steps per turn through the graph's recursion limit, tokens per turn through the counters the graph state already carries, seconds per turn through a timeout around the graph invocation, and USD per UTC day through the same cost fold that feeds `kinby stats`, checked before a turn starts. A tripped budget closes the turn as `turn.failed` with a budget error code and no wrap-up model call, because a final call spends the thing the budget protects, and `turn.interrupted` stays reserved for the user stopping a turn. When a daily cost budget is set and the turn's model is absent from the price map, the turn refuses to start rather than run unmetered, matching ADR 0018's refusal to report unknown cost as zero. Absent keys mean no limit, and a routine may lower any budget but never raise one.
