# Deletion deletes the previewed inventory and releases each target

An **instance deletion** works only on a removed instance, and only on what its storage inventory records as writable. A read-only mount was never reserved against other instances, so it is not the instance's to delete. The hub never reads the manifest for targets, so a directory the manifest references stays. `instance.delete.preview` lists the targets: each writable bind as a directory the hub resolves on its own filesystem, and each writable named volume by name. The instance directory is the path the registry records, because that is where the hub sees it. The Docker host may mount it from elsewhere.

`instance.delete` carries the previewed lists back. Under the instance's lifecycle lock, the hub resolves the targets again and compares. If anything changed, it refuses and deletes nothing, and the client previews again. The hub never swaps a changed target for a new one without a new preview. The hub also refuses when any other record names the storage, including removed records and read-only mounts, with the same alias and overlap rules adoption uses. It refuses as well when a container stands under the instance's runtime id.

Each target is its own step of the operation. The hub deletes the target first and then drops its inventory entries. A retry therefore finds the targets that failed and never the ones that are gone, even if something unrelated later appears at the same path or under the same volume name. A directory or volume that is already missing counts as deleted, so a retry after an interruption can finish. Once every target is gone, the record becomes "deleted", a fourth intended state. It leaves both lists and recovery, and its operations stay readable. Recovery reports a removed instance whose last delete failed and tells the user to preview again.

Decision agreed during [Preview and permanently delete retained instance storage](https://github.com/jorgesolerrr/kinby/issues/244), under [ADR 0053](0053-removal-retains-the-record-and-restoration-is-explicit.md).
